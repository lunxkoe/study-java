# 문자 인코딩

## 컴퓨터와 데이터

### 텍스트 데이터 원리의 이해가 필요한 이유
- 이해하지 못하면 한글 글자가 이상하게 깨져서 나올 때, 근본적인 원인을 찾아서 해결하기 어려움

### 컴퓨터 메모리
- 반도체로 만들어짐(수많은 전구들이 모여있는 것)
- 전구 = 트랜지스터
  - 전기가 흐르거나 흐르지 않는 두 가지 상태를 가질 수 있음(0과 1)
- 컴퓨터가 정보를 저장하거나 처리할 때, 이 전구들을 켜고 끄는 방식으로 데이터를 기록하고 읽어들임

### 2진수
- 전구가 꺼짐과 켜짐 = 0과 1
- 0 = 0 / 1 = 1 
- 10 = 2 / 11 = 3
- 100 = 4 / 101 = 5
- 전구 = 1bit

### 1bit * N
- 1 bit = 2가지 표현
- 2 bit = 2 * 2가지 표현
- 3 bit = 2 * 2 * 2가지 표현
- N bit = 2 ^ N가지 표현
- 참고: 8bit = 1byte = 256가지 표현

### 숫자 저장 예시
- 10진수 100을 컴퓨터에 저장하려면?
  - 컴퓨터는 10진수를 이해하지 못함 => 2진수로 전환이 필요함
  - 100(10) = 1100100(2)

### 음수 표현
- 처음 1bit를 음수, 양수를 표현하는데 사용함
  - 0과 양수만 표현하는 경우 (0 ~ 255)
    - 8bit 모두 숫자 표현에 사용
  - 음수 표현이 필요한 경우
    - 맨 앞의 1bit는 음수와 양수를 구분하는데 사용, 나머지 7bit 숫자 범위 사용
    - 0 ~ 127 (양수 표현시 첫 비트를 0으로 사용, 나머지 7bit로 128가지 0과 양수 숫자 표현)
    - -128 ~ -1 (음수 표현 시 첫 비트를 1로 사용, 나머지 7bit로 128가지 음수 수자 표현)

## 컴퓨터와 문자 인코딩 1

### 문자는 어떻게 저장할까?
- 문자를 이진수로 변환하는 공식은 세상에 존재하지 않음
- 해결: 문자 집합을 만들고, 각 문자에 숫자를 연결시키는 방법
- 동작:
  - 문자 A를 문자 집합(A : 65)의 65로 변환해서 저장 = **인코딩**
  - 65를 문자 집합(65 : A)의 A로 변환해서 출력 = **디코딩**

### ASCII 문자 집합
- 7bit를 사용하면 128가지 문자를 표현할 수 있음
- 공식 문자 집합 ASCII가 탄생

### ISO_8859_1
- 서유럽을 중심으로 컴퓨터 사용 인구가 늘어나면서, 서유럽 문자를 표현하는 문자 집합이 필요해짐
- 8bit로 확장 = 기존 ASCII(0 ~ 127) + 확장(128 ~ 255)
- 기존 ASCII 호환

### 한글 문자 집합
- EUC-KR
  - 모든 한글을 담는 것보다는 자주 사용하는 한글 2350개만 포함해서 만듦
  - 한글은 글자가 아주 많기 때문에 256가지만 표현할 수 있는 1byte로 표현하는 것은 불가능함
  - **2byte**를 사용하면 총 65536가지 표현 가능
  - 특징:
    - 영어를 사용하면 1byte로 메모리에 저장
    - 한글을 사용하면 2byte로 메모리에 저장

## 컴퓨터와 문자 인코딩 2

### 전세계 문잡 집합
- 문제
  - EUC-KR이나 MS949같은 한글 문자표를 PC에 설치하지 않으면 다른 나라 사람들은 한글로 작성된 문서를 열어볼 수 없음

- 유니코드가 등장
  - 위의 문제를 해결하기 위해서 세계의 모든 문자들을 단일 문자 세트로 표현할 수 있는 유니코드(Unicode) 표준이 도입
  - UTF-16, UTF-8의 시작
  - 두 표준이 비슷하게 등장, 초반에는 UTF-16이 인기

### UTF-16
- 16bit 기반
- 자주 사용하는 기본 다국어들은 2byte로 표현
  - 영어, 유럽, 한국어, 중국어, 일본어 등이 2byte를 사용
- 그 외에는 4byte로 표현 (42억 가지)
  - 고대 문자, 이모지, 중국어 확장 한자 등
- 단점:
  - ASCII 영문도 2byte를 사용함 + ASCII와 호환되지 않음
    - UTF-16을 사용한다면 영문의 경우 다른 문자 집합보다 2배의 메모리를 더 사용함
    - 웹에 있는 문서의 80% 이상은 영문으로 작성되어있음
- 자바의 언어 내부적으로 문자를 표현할 때, UTF-16을 사용함. **그래서 자바의 char 타입이 2byte를 사용함**

### UTF-8
- 8bit 기반, 가변 길이 인코딩
- 1byte ~ 4byte를 사용해서 문자를 인코딩
  - 1byte: ASCII 영문, 기본 라틴 문자
  - 2byte: 그리스어, 히브리어 라틴 확장 문자
  - 3byte: **한글**, 한자, 일본어
  - 4byte: 이모지, 고대 문자 등
- 단점: 상대적으로 사용이 복잡함
- 단점: ASCII를 제외한 일부 언어에서 더 많은 용량 사용
- 장점: ASCII 문자는 1바이트로 표현 및 호환
- 결론: ** 최신은 UTF-8을 사용하자**

## 문자 집합 조회

### 이용 가능한 문자 집합 조회
```java
public class AvailableCharsetsMain {

    public static void main(String[] args) {
        // 이용 가능한 모든 Charset 자바 + OS
        SortedMap<String, Charset> charsets = Charset.availableCharsets();
        for (String charSetName : charsets.keySet()) {
            System.out.println("charSetName = " + charSetName);
        }

        System.out.println("=====");
        // 문자로 조회(대소문자 구분 X)
        Charset charset1 = Charset.forName("MS949");
        System.out.println("charset1 = " + charset1);

        // 별칭 조회
        Set<String> aliases = charset1.aliases();
        for (String alias : aliases) {
            System.out.println("alias = " + alias);
        }

        // UTF-8 문자로 조회
        Charset charset2 = Charset.forName("UTF-8");
        System.out.println("charset2 = " + charset2);

        Charset charset3 = StandardCharsets.UTF_8; // 자주 사용하므로 상수로 정의되어있음
        System.out.println("charset3 = " + charset3);

        // 시스템의 기본 Charset 조회
        Charset defaultCharset = Charset.defaultCharset();
        System.out.println("defaultCharset = " + defaultCharset);
    }
}
```
- 파일을 저장할 때 문자 집합을 지정해주어야함
- 지정하지 않으면 시스템의 기본 Charset으로 지정되어 저장함

## 문자 인코딩 예제 1

### 예제 코드
```java
public class EncodingMain1 {

    private static final Charset EUC_KR = Charset.forName("EUC_KR");
    private static final Charset MS_949 = Charset.forName("MS_949");

    public static void main(String[] args) {
        System.out.println("== ASCII 영문 처리 ==");
        encoding("A", US_ASCII);
        encoding("A", ISO_8859_1);
        encoding("A", EUC_KR);
        encoding("A", UTF_8);
        encoding("A", UTF_16BE); // 2byte를 사용, 호환이 안됨

        System.out.println("== 한글 지원 ==");
        encoding("가", EUC_KR);
        encoding("가", MS_949);
        encoding("가", UTF_8);
        encoding("가", UTF_16BE);
    }

    private static void encoding(String text, Charset charset) {
        byte[] bytes = text.getBytes(charset);
        System.out.printf("%s -> [%s] 인코딩 -> %s %sbyte\n", text, charset, Arrays.toString(bytes), bytes.length);
    }
}
```
- 실행 결과
```text
== ASCII 영문 처리 ==
A -> [US-ASCII] 인코딩 -> [65] 1byte
A -> [ISO-8859-1] 인코딩 -> [65] 1byte
A -> [EUC-KR] 인코딩 -> [65] 1byte
A -> [UTF-8] 인코딩 -> [65] 1byte
A -> [UTF-16BE] 인코딩 -> [0, 65] 2byte
== 한글 지원 ==
가 -> [EUC-KR] 인코딩 -> [-80, -95] 2byte
가 -> [x-windows-949] 인코딩 -> [-80, -95] 2byte
가 -> [UTF-8] 인코딩 -> [-22, -80, -128] 3byte
가 -> [UTF-16BE] 인코딩 -> [-84, 0] 2byte
```
- 문자를 바이트로 변환할 때는 **무조건 문자 집합이 필요함**
- String.getBytes(Charset) 사용 / 지정하지 않으면 시스템 기본 문자 집합 사용

### 정리
- ASCII 영문 인코딩: UTF-16을 제외하고 모두 호환
- **사실상 표준인 UTF-8을 사용하자**
  - 영문: 1바이트
  - 한글: 3바이트

### 어떻게 UTF-8을 사용하면 영문인지 한글이지 구분하는 것일까?
- UTF-8로 저장할 때, 첫 바이트에 비트 패턴을 적용함 (해당 글자가 몇 바이트인지를 적어둠)
  - 1바이트: 0xxxxxxx
  - 2바이트: 110xxxxx
  - 3바이트: 1110xxxx
  - 4바이트: 11110xxx
  - 이어지는 바이트(시작이 아니라는 의미): 10xxxxxx

### 한글이 깨지는 가장 큰 2가지 이유
- EUC-KR(MS949) <-> UTF-8 서로 호환되지 않음
- EUC-KR(MS949) / UTF-8로 인코딩한 한글을 ISO-8859-1로 디코딩 할 때
  - 한글을 지원하지 않는 문자 집합으로 디코딩하는 경우 깨짐

### 주의할 점
- 자바는 내부적으로 String을 UTF-16으로 저장함
  - Java 9부터는 문자열 전체가 Latin-1 범위 문자로만 이루어져 있으면 1바이트 Latin-1로 저장
  - 한 글자라도 Latin-1 범위를 벗어나면 문자열 전체를 UTF-16으로 저장
  - 이건 JVM 내부의 저장 방식일 뿐이고, getBytes(charset)을 호출하면
    지정한 charset 규칙에 맞게 인코딩된 새 byte[]를 반환함 (원본 String은 그대로)
- 예시
  - "A"   -> JVM 내부 메모리에 1바이트로 저장 (Latin-1)
  - "A가" -> JVM 내부 메모리에 4바이트로 저장 (UTF-16)
  - "A".getBytes(UTF_16BE) -> 2바이트 [0, 65]
  - "A".getBytes(UTF_16)   -> 4바이트 [-2, -1, 0, 65] (앞 2바이트는 BOM)
- String.getBytes(charset)은 UTF-16을 지정한 charset으로 변환해주는 작업을 대신 해주는 메서드
- String.getBytes(charset)
  - 해당 문자열을 지정한 charset으로 인코딩 해줘라는 의미
- new String(byte[] bytes, charset)
  - bytes를 지정한 charset으로 디코딩 해줘라는 의미
  - 디코딩 시에는 가능하면 인코딩할 때 사용한 charset과 같은 걸 서야 복원됨
