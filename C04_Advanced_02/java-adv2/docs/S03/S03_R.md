# I/O 기본 1

## 스트림 시작 1

### 데이터 저장
- 자바가 가진 데이터를 hello.dat라는 파일에 저장하려면 어떻게 해야할까?
- 자바가 가진 데이틀 밖으로 내보내려면 `출력 스트림`을 사용하면 됨
- 외부 데이터를 자바 프로세스 안으로 가지고 오려면 `입력 스트림`을 사용하면 됨
- **각 스트림은 `단방향`으로 흐름**

### 예제 코드
```java
public class StreamStartMain1 {

    public static void main(String[] args) throws IOException {
        FileOutputStream fos = new FileOutputStream("temp/hello.dat");
        fos.write(65);
        fos.write(66);
        fos.write(67);
        fos.close();

        FileInputStream fis = new FileInputStream("temp/hello.dat");
        System.out.println(fis.read());
        System.out.println(fis.read());
        System.out.println(fis.read());
        System.out.println(fis.read()); // -1: 파일의 끝이라는 의미
        fis.close();
    }
}
```

### new FileOutputStream("temp/hello.dat")
- 파일에 데이터를 출력하는 스트림
- 파일이 없으면 자동으로 만들고, 데이터를 해당 파일에 저장함
- 폴더를 만들지 않기 때문에 폴더는 미리 만들어두어야 함

### write()
- `byte 단위`로 값을 출력함
- 여기서 65, 66, 67을 출력함
- 참고로 ASCII 문자 집합에서 65 = 'A', 66 = 'B', 67 = 'C'

### new FileInputStream("temp/hello.dat")
- 파일에서 데이터를 읽어오는 스트림

### read()
- 파일에서 데이터를 byte 단위로 하나씩 읽어옴
- 순서대로 65, 66, 67을 읽어옴
- 파일의 끝에 도달해서 더는 읽을 내용이 없다면 `-1`을 반환함
    - 파일의 끝(EOF, End Of File)

### close()
- 파일에 접근하는 것은 자바 입장에서 외부 자원을 사용하는 것
- 자바 내부 객체는 자동으로 GC가 되지만 외부 자원은 사용 후 반드시 닫아주어야함 (자원 정리)

### 실행 결과
- console
```text
65
66
67
-1
```

- temp/hello.dat
```text
ABC
```
- hello.dat에는 분명 65, 66, 67을 저장함
- 왜 개발툴이나 텍스트 편집기에서 열어보면 ABC라고 보이는 것일까
- 개발툴이나 텍스트 편집기는 UTF-8 또는 MS949 문자 집합을 사용해서 byte 단위의 데이터를 문자로 디코딩해서 보여줌
- 따라서 byte를 ASCII A, B, C로 인식해서 출력한 것

### 참고: 파일 append 옵션
- FileOutputStream의 생성자는 append라는 옵션이 있음
- `new FileOutputStream("temp/hello.dat", true)`
    - true: 기존 파일의 끝에 이어서 작성
    - false: 기존 파일의 데이터를 지우고 처음부터 다시 씀 (기본값)

### 예제 코드
```java
public class StreamStartMain2 {

    public static void main(String[] args) throws IOException {
        FileOutputStream fos = new FileOutputStream("temp/hello.dat");
        fos.write(65);
        fos.write(66);
        fos.write(67);
        fos.close();

        FileInputStream fis = new FileInputStream("temp/hello.dat");
        int data;
        while (-1 != (data = fis.read())) {
            System.out.println(data);
        }
        fis.close();
    }
}
```

### 참고: read()가 int를 반환하는 이유
- 부호 없는 바이트 표현
    - 자바에서 byte는 부호 있는 8비트 값(-128 ~ 127)
    - int를 반환함으로써 0에서 255까지의 모든 가능한 바이트 값을 부호 없이 표현할 수 있음
- EOF 표시
    - byte를 표현하려면 256 종류의 값을 모두 사용해야함
    - 자바의 byte는 -128에서 127까지 256종류의 값만 가질 수 있어, EOF를 위한 특별한 값을 할당하기 어려움
    - int는 0 ~ 255까지 모든 가능한 바이트 값을 표현하고, 여기에 추가로 -1을 반환하여 스트림의 끝(EOF)를 나타낼 수 있음
- write()의 경우도 비슷한 이유로 int 타입을 입력 받음
- 읽은 값은 다시 바이트로 사용할 때는 `(byte) v`로 캐스팅해서 사용함

## 스트림 시작 2

### 예제 코드
- `byte`를 하나씩 다루는 것이 아니라 `byte[]`를 사용해서 데이터를 원하는 크기만큼 저장하고 읽는 방법
```java
public class StreamStartMain3 {

    public static void main(String[] args) throws IOException {
        FileOutputStream fos = new FileOutputStream("temp/hello.dat");
        byte[] input = {65, 66, 67};
        fos.write(input);
        fos.close();

        FileInputStream fis = new FileInputStream("temp/hello.dat");
        byte[] buffer = new byte[10];
        int readCount = fis.read(buffer, 0, 10);
        System.out.println("readCount = " + readCount);
        System.out.println(Arrays.toString(buffer));
        fis.close();
    }
}
```

### 실행 결과
- console
```text
readCount = 3
[65, 66, 67, 0, 0, 0, 0, 0, 0, 0]
```

- temp/hello.dat
```text
ABC
```

### 출력 스트림
- `write(byte[])`: byte[]에 원하는 데이터를 담고, write()에 전달하면 해당 데이터를 한 번에 출력할 수 있음

### 입력 스트림
- `read(byte[], offset, length)`: byte[]를 미리 만들어두고, 만들어 둔 byte[]에 한 번에 데이터를 읽어올 수 있음
- byte[]: 데이터가 읽혀지는 버퍼
- offset: 데이터가 기록되는 byte[]의 인덱스 위치
- length: 읽어올 byte의 최대 길이
- 반환 값: 버퍼에 읽은 총 바이트 수, 여기서는 3byte를 읽었으므로 3이 반환됨
    - 스트림의 끝에 도달하여 더 이상 데이터가 없는 경우 -1을 반환
        - 이런 상황은 보통 반복적인 읽기 상황에서 나옴

### read(byte[])
- 참고로 offset, length를 생략한 read(byte[]) 메서드도 있음
    - offset: 0
    - length: byte[].length

### 예제 코드
- 모든 byte를 한 번에 읽기 - readAllBytes()
```java
public class StreamStartMain4 {

    public static void main(String[] args) throws IOException {
        FileOutputStream fos = new FileOutputStream("temp/hello.dat");
        byte[] input = {65, 66, 67};
        fos.write(input);
        fos.close();

        FileInputStream fis = new FileInputStream("temp/hello.dat");
        byte[] readBytes = fis.readAllBytes();
        System.out.println(Arrays.toString(readBytes));
        fis.close();
    }
}
```

### 실행 결과
- console
```text
[65, 66, 67]
```

### 부분으로 나누어 읽기 vs 전체 읽기
- read(byte[], offset, length)
    - 스트림의 내용을 부분적으로 읽거나, 읽은 내용을 처리하면서 스트림을 계속해서 읽어야 할 경우에 적합함
    - 메모리 사용량을 제어할 수 있음
    - 파일이나 스트림에서 일정한 크기의 데이터를 반복적으로 읽어야할 때 유용함
        - 대용량 파일을 처리할 때, 한 번에 메모리에 로드하기보다는 이 메서드를 사용해서 파일을 조각조각 읽어들일 수 있음
        - 100M 파일을 1MB 단위로 나누어 읽고 처리하는 방식을 사용하면 최대 1M 메모리만 사용함
- readAllBytes()
    - 한 번에 호출로 모든 데이터를 읽을 수 있어 편리함
    - 작은 파일이나 메모리에 모든 내용을 올려서 처리해야하는 경우에 유용함
    - 메모리 사용량을 제어할 수 없음
    - 큰 파일의 경우 OutOfMemoryError가 발생할 수 있음

## InputStream, OutputStream

### 데이터 통신
- 컴퓨터는 대부분 byte 단위로 데이터를 주고 받음
- 이렇게 데이터를 주고 받는 것을 Input/Output(I/O)라고 함
- **파일, 네트워크, 콘솔 각각 데이터를 주고 받는 방식이 다르면 상당히 불현할 것임**
    - InputStream, OutputStream이라는 기본 추상 클래스를 제공함

### InputStream
- 인터페이스
- 구현체
    - File InputStream
    - ByteArray InputStream
    - Socket InputStream
- 메서드
    - read()
    - read(byte[])
    - readAllBytes()

### OutputStream
- 인터페이스
- 구현체
    - File OutputStream
    - ByteArray OutputStream
    - Socket OutputStream
- 메서드
    - write(int)
    - write(byte[])
    - int: 실제로 쓰이는 건 하위 8비트
        - write(-1): EOF 같은 특별한 의미가 아니라, 그냥 바이트 0xFF를 쓰는 것 뿐

### 메모리 스트림
```java
public class ByteArrayStreamMain {

    public static void main(String[] args) throws IOException {
        byte[] input = {1, 2, 3};

        // 메모리에 쓰기
        ByteArrayOutputStream baos = new ByteArrayOutputStream();
        baos.write(input);

        // 메모리에서 읽기
        ByteArrayInputStream bais = new ByteArrayInputStream(baos.toByteArray());
        byte[] bytes = bais.readAllBytes();
        System.out.println("bytes = " + Arrays.toString(bytes));
    }
}
```

### 실행 결과
- console
```text
bytes = [1, 2, 3]
```

### 설명
- ByteArrayOutputStream, ByteArrayInputStream을 사용하면 메모리에 스트림을 쓰고 읽을 수 있음
- 참고로 메모리에 어떤 데이터를 저장하고 읽을 때는 컬렉션이나 배열을 사용하면 되기 때문에, 이 기능은 잘 사용하지 않음
- 주로 스트림을 간단하게 테스트하거나 스트림의 데이터를 확인하는 용도로 사용함

### 콘솔 스트림
```java
public class PrintStreamMain {

    public static void main(String[] args) throws IOException {
        System.out.println("Hello");

        PrintStream printStream = System.out;
        printStream.println("Hello");

        byte[] bytes = "Hello!\n".getBytes(UTF_8);
        printStream.write(bytes);
        printStream.println("Print!");
    }
}
```

### 실행 결과
```text
Hello
Hello
Hello!
Print!
```

### 설명
- 우리가 사용했던 System.out은 사실은 PrintStream
- 이 스트림은 OutputStream을 상속 받음
- 자바가 시작될 때 자동으로 만들어짐, 직접 생성하지 않음
    - write(byte[]): OutputStream 부모 클래스가 제공하는 기능
    - println(String): PrintStream이 자체적으로 제공하는 추가 기능
        - String을 내부적으로 byte로 변환해서 저장함

### 정리
- InputStream, OutputStream이 다양한 스트림들을 추상화하고 기본 기능에 대한 표준을 잡아둔 덕분에 개발자는 편하게 입출력 작업을 수행할 수 있음
- 일관성
- 유연성
- 확장성
- 재사용성
- 에러 처리
- 참고: 인터페이스가 아닌 `추상 클래스`, 일부 작동하는 코드도 들어있음

## 파일 입출력과 성능 최적화 1 - 하나씩 쓰기

### 상수 정의
```java
public class BufferedConst {

    public static final String FILE_NAME = "temp/buffered.dat";
    public static final int FILE_SIZE = 10 * 1024 * 1024; // 10MB
    public static final int BUFFERED_SIZE = 8192; // 8KB
}
```
- FILE_NAME: temp/buffered.dat라는 파일을 만들 예정
- FILE_ZIE: 파일의 크기는 10MB
- BUFFER_SIZE는 뒤에서 설명

### 예제 코드 - 쓰기
```java
public class CreateFileV1 {

    public static void main(String[] args) throws IOException {
        FileOutputStream fos = new FileOutputStream(FILE_NAME);

        long startTime = System.currentTimeMillis();

        for (int i = 0; i < FILE_SIZE; i++) {
            fos.write(1);
        }
        fos.close();

        long endTime = System.currentTimeMillis();
        System.out.println("File created: " + FILE_NAME);
        System.out.println("File size: " + FILE_SIZE / 1024 / 1024 + "MB");
        System.out.println("Time taken: " + (endTime - startTime) + "ms");
    }
}
```

### 실행 결과
```text
File created: temp/buffered.dat
File size: 10MB
Time taken: 28569ms
```

### 예제 코드 - 읽기
```java
public class ReadFileV1 {

  public static void main(String[] args) throws IOException {
    FileInputStream fis = new FileInputStream(FILE_NAME);

    long startTime = System.currentTimeMillis();

    int fileSize = 0;
    int data;
    while (-1 != (data = fis.read())) {
      fileSize++;
    }
    fis.close();

    long endTime = System.currentTimeMillis();
    System.out.println("File name: " + FILE_NAME);
    System.out.println("File size: " + (fileSize / 1024 / 1024) + "MB");
    System.out.println("Time taken: " + (endTime - startTime) + "ms");
  }
}
```

### 실행 결과
```text
File name: temp/buffered.dat
File size: 10MB
Time taken: 19243ms
```
- fis.read()를 사용해서 `1byte`씩 데이터를 읽음
- 10MB = 10 * 1024 * 1024 (약 1000만)번을 호출함

### 정리
- 10MB 파일 하나를 쓰는데, 28초, 19초 (컴퓨터 사양에 따라 다름)씩 매우 오랜 시간이 걸림
- 이유
    - 1byte씩 디스크에 데이터를 전달하기 때문
    - 이 과정을 1000만법 반복
- 조금 더 자세한 이유
    - write(), read()를 호출할 때마다 OS의 시스템 콜을 통해 파일을 읽거나 쓰는 명령어를 전달함
    - 시스템 콜은 상대적으로 무거운 작업
    - HDD, SSD 같은 장치들도 하나의 데이터를 읽고 쓸 때마다 필요한 시간이 있음
    - 이러한 무거운 작업을 1000만 번 반복함
- 해결 방안
    - 한 번에 더 많은 상품을 담아서 보내면 됨

### 참고
- 자바에서 운영체제를 통해 디스크에 1byte씩 전달하면, 운영체제나 하드웨어 레벨에서 여러가지 최적화가 발생함
- 실제로 디스크에 1byte식 계속 쓰는 건 아님
- read(), write() 호출 횟수를 줄여서 시스템 콜 횟수도 줄여야 함

## 파일 입축력과 성능 최적화 2 - 버퍼 활용

### 예제 코드 - 쓰기
```java
public class CreateFileV2 {

    public static void main(String[] args) throws IOException {
        FileOutputStream fos = new FileOutputStream(FILE_NAME);

        long startTime = System.currentTimeMillis();

        byte[] buffer = new byte[BUFFERED_SIZE];
        int bufferIndex = 0;
        for (int i = 0; i < FILE_SIZE; i++) {
            buffer[bufferIndex++] = 1;

            // 버퍼가 가득 차면 쓰고, 버퍼를 비움
            if (bufferIndex == BUFFERED_SIZE) {
                fos.write(buffer);
                bufferIndex = 0;
            }
        }

        // 끝 부분에 오면 버퍼가 가득차지 않고, 남아 있을 수 있음
        if (bufferIndex > 0) {
            fos.write(buffer, 0, bufferIndex);
        }

        fos.close();

        long endTime = System.currentTimeMillis();
        System.out.println("File created: " + FILE_NAME);
        System.out.println("File size: " + (FILE_SIZE / 1024 / 1024) + "MB");
        System.out.println("Time taken: " + (endTime - startTime) + "ms");
    }
}
```

### 실행 결과
```text
File created: temp/buffered.dat
File size: 10MB
Time taken: 31ms
```
- 데이터를 먼저 buffer라는 byte[]에 담아둠
    - 이렇게 데이터를 모아서 전달하거나 모아서 전달받는 용도로 사용하는 것을 버퍼라고 함
- BUFFER_SIZE만큼 데이터를 모아서 write()를 호출함
    - BUFFER_SIZE가 10이라면 10만큼 모이면 write()를 호출해서 10Byte를 한 번에 스트림에 전달함
- 1byte씩 쓸때보다 900배 빨라진 것을 확인할 수 있음

### 버퍼의 크기에 따른 쓰기 성능
- 1: 28569ms
    - 10 * 1024 * 1024(10,485,760)번의 시스템 콜 호출
- 8192: 31ms
    - (10 * 1024 * 1024) / 8192(1,280)번의 시스템 콜 호출
- 실행 속도 시간이 약 921배 정도 빨라짐
- 주의
    - 버퍼 사이즈가 일정 수준 이상 넘어가면 더 이상 빨라지지 않음
    - 디스크나 파일 시스템에서 데이터를 읽고 쓰는 기본 단위가 보통 4KBm 8KB이기 때문임
    - 저장하는 효율에 한계가 있음

### 예제 코드 - 읽기
```java
public class ReadFileV2 {

    public static void main(String[] args) throws IOException {
        FileInputStream fis = new FileInputStream(FILE_NAME);

        long startTime = System.currentTimeMillis();

        byte[] buffer = new byte[BUFFERED_SIZE];
        int fileSize = 0;
        int readCount;
        while (-1 != (readCount = fis.read(buffer))) {
            fileSize += readCount;
        }
        fis.close();

        long endTime = System.currentTimeMillis();
        System.out.println("File name: " + FILE_NAME);
        System.out.println("File size: " + (fileSize / 1024 / 1024) + "MB");
        System.out.println("Time taken: " + (endTime - startTime) + "ms");
    }
}
```

### 실행 결과
```text
File name: temp/buffered.dat
File size: 10MB
Time taken: 8ms
```
- 1byte씩 읽었을 때: 19243ms
- 8192byte씩 읽었을 때: 8ms
- 약 2,405배의 성능 향상

### 정리
- 버퍼를 사용하면, 직접 버퍼를 만들고 관리해야하는 번거로운 단점이 있음
- 단순한 코드를 유지하면서, 버퍼를 사용할 때와 같은 성능의 이점을 누리는 방법은 없을까?

## 파일 입출력과 성능 최적화 3 - Buffered 스트림 쓰기

### BufferedOutputStream
- 버퍼 기능을 내부에서 대신 처리해줌

### 예제 코드
```java
public class CreateFileV3 {

    public static void main(String[] args) throws IOException {
        FileOutputStream fos = new FileOutputStream(FILE_NAME);
        BufferedOutputStream bos = new BufferedOutputStream(fos, BUFFERED_SIZE);

        long startTime = System.currentTimeMillis();

        for (int i = 0; i < FILE_SIZE; i++) {
            bos.write(1);
        }
        bos.close();

        long endTime = System.currentTimeMillis();
        System.out.println("File created: " + FILE_NAME);
        System.out.println("File size: " + (FILE_SIZE / 1024 / 1024) + "MB");
        System.out.println("Time taken: " + (endTime - startTime) + "ms");
    }
}
```

### 실행 결과
```text
File created: temp/buffered.dat
File size: 10MB
Time taken: 307ms
```

### BufferedOutputStream
- 내부에서 단순히 버퍼 기능을 제공함
- 따라서 반드시 대상 OutputStream이 있어야함
- 여기서는 FileOutputStream 객체를 생성자에 전달함
- 추가로 사용할 버퍼의 크기도 함께 전달할 수 있음

### BufferedOutputStream 분석
- OutputStream
    - FileOutputStream
        - BufferedOutputStream

### BufferedOutputStream 실행 순서
- byte[] buf라는 버퍼를 가지고 있음
- write(byte)를 통해 byte를 하나 전달하면 byte[] buf에 보관함
    - 참고로 실제로는 write(int) 타입이지만 쉽게 설명하기 위해 write(byte)로 그려둠
- 버퍼가 가득차면 FileOutputStream에 있는 write(byte[]) 메서드를 호출함
    - 참고로 BufferedOutputStream의 생성자에 FileOutputStream, fos를 전달해두었음
    - FileOutputStream에 있는 write(byte[])를 호출하면 전달된 모든 byte[]는 시스템 콜로 OS에 전달함
- 이후 버퍼를 비우고 다시 채움

- flush()
    - 버퍼가 다 차지 않아도 버퍼에 남아있는 데이터를 전달하려면 flush() 메서드를 호출하면 됨

- close()
    - 버퍼에 데이터가 남아있는 상태로 close()를 호출하면
        - 먼저 내부에 flush()를 호출하고 정리함
        - BufferedOutputStream의 close()로 자원 정리
        - FileOutputStream의 close()로 자원 정리

### 주의: 반드시 마지막에 연결한 스트림을 닫아야함
- 위의 코드에서 bos가 아닌 fos를 close()를 하면
- bos의 flush()도 호출되지 않고, 자원도 정리되지 않음
- 따라서 남은 byte가 버퍼에 남아있게 되고, 파일에 저장되지 않는 심각한 문제가 발생함

### 기본 스트림, 보조 스트림
- FileOutputStream과 같이 사용할 수 있는 스트림을 기본 스트림이라고 함
- BufferedOutputStream과 같이 단독으로 사용할 수 없고, 보조 기능을 제공하는 스트림을 보조 스트림이라고 함

### 정리
- BufferedOutputStream은 버퍼 기능을 제공하는 보조 스트림
- OutputStream의 자식이기 때문에 기능을 그대로 사용할 수 있음
    - 물론 대부분의 기능은 재정의됨
    - write()의 경우 먼저 버퍼에 쌓도록 재정의 됨
- 버퍼의 크기만큼 데이터를 모다서 전달하기 때문에 빠른 속도로 데이터를 처리할 수 있음
    - size 기본: 4KB, 8KB
    - 직접 버퍼를 만들었던 예제보다는 느림: 내부적으로 동기화 코드가 있기 때문

## 파일 입출력과 성능 최적화 4 - Buffered 스트림 읽기

### 예제 코드
```java
public class ReadFileV3 {

    public static void main(String[] args) throws IOException {
        FileInputStream fis = new FileInputStream(FILE_NAME);
        BufferedInputStream bis = new BufferedInputStream(fis, BUFFERED_SIZE);

        long startTime = System.currentTimeMillis();

        int fileSize = 0;
        int data;
        while (-1 != (data = bis.read())) {
            fileSize++;
        }
        bis.close();

        long endTime = System.currentTimeMillis();
        System.out.println("File name: " + FILE_NAME);
        System.out.println("File size: " + (fileSize / 1024 / 1024) + "MB");
        System.out.println("Time taken: " + (endTime - startTime) + "ms");
    }
}
```

### 실행 결과
```text
File name: temp/buffered.dat
File size: 10MB
Time taken: 272ms
```

### BufferedInputStream 분석
- InputStream
    - FileInputStream
    - BufferedInputStream

### BufferedInputStream 실행 순서
- read(byte[])로 버퍼에 데이터를 채움
    - 시스템 콜 발생
- read()를 호출하면 버퍼에 있는 데이터 중 1byte를 반환함
    - 배열에서 1바이트 꺼내기만 하면 됨 (시스템 콜 X)

```java
public synchronized int read() throws IOException {
    if (pos >= count) {           // 버퍼에 읽을 데이터가 없으면
        fill();                    // 내부 버퍼(byte[])를 fis.read(buf)로 가득 채움
        if (pos >= count)          // 채웠는데도 없으면 (파일 끝)
            return -1;
    }
    return getBufIfOpen()[pos++] & 0xff;  // 버퍼에서 1바이트 꺼내서 반환
}
```

### 버퍼를 직접 다루는 것보다 BufferedXxx의 성능이 떨어지는 이유
- **동기화 때문!!**
- BufferedXxx 클래스의 특징
    - 1byte를 쓸 때마다, 락을 걸고 풀고를 반복함
    - 처음부터 멀티스레드를 고려해서 만든 클래스
    - 싱글 스레드 상황에서는 동기화 락이 필요하지 않기 때문에 직접 버퍼를 다룰 때와 비교해서 성능이 떨어짐
    - 동기화 락이 없는 BufferedXxx 클래스는 없음
        - 꼭 필요한 상황이라면 BufferedXxx를 참고해서 동기화 락 코드를 제거한 클래스를 직접 만들어 사용

## 파일 입출력과 성능 최적화 5 - 한 번에 쓰기

### 예제 코드
- 파일의 크기가 크지 않다면, 한 번에 쓰고 읽는 것도 좋은 방법
- 성능은 가장 빠르지만, 결과적으로 메모리를 한 번에 많이 사용하기 때문에 파일의 크기가 작아야 함
```java
public class CreateFileV4 {

    public static void main(String[] args) throws IOException {
        FileOutputStream fos = new FileOutputStream(FILE_NAME);
        long startTime = System.currentTimeMillis();

        byte[] buffer = new byte[FILE_SIZE]; // 10MB
        for (int i = 0; i < FILE_SIZE; i++) {
            buffer[i] = 1;
        }
        fos.write(buffer);
        fos.close();

        long endTime = System.currentTimeMillis();
        System.out.println("File created: " + FILE_NAME);
        System.out.println("File size: " + (FILE_SIZE / 1024 / 1024) + "MB");
        System.out.println("Time taken: " + (endTime - startTime) + "ms");
    }
}
```

### 실행 결과
```text
File created: temp/buffered.dat
File size: 10MB
Time taken: 26ms
```
- 무조건 한 번에 쓴다고 성능이 극적으로 빨라지지 않음
- 파일에 쓸 수 있는 최대 용량이 4, 8KB이기 때문

### 예제 코드
```java
public class ReadFileV4 {

    public static void main(String[] args) throws IOException {
        FileInputStream fis = new FileInputStream(FILE_NAME);
        long startTime = System.currentTimeMillis();

        byte[] bytes = fis.readAllBytes();
        fis.close();

        long endTime = System.currentTimeMillis();
        System.out.println("File name: " + FILE_NAME);
        System.out.println("File size: " + (bytes.length / 1024 / 1024) + "MB");
        System.out.println("Time taken: " + (endTime - startTime) + "ms");
    }
}
```

### 실행 결과
```text
File name: temp/buffered.dat
File size: 10MB
Time taken: 11ms
```
- 실행 시간은 8KB의 버퍼를 사용한 예제 2와 오차 범위 정도로 거의 비슷함
- 자바 구현에 따라 다르지만 보통 4, 8, 16KB 단위로 데이터를 읽어들임

## 정리

### 정리
- 파일의 크기가 크지 않아서, 메모리 사용에 큰 영향을 주지 않는다면 쉽고 빠르게 한 번에 처리
- 성능이 중요하고 큰 파일을 나우어 처리해야 한다면, 버퍼를 직접 다루기
- 성능이 크게 중요하지 않고, 버퍼 기능이 필요하면 BufferedXxx를 사용하자
    - 동기화 코드가 들어있어서 스레드 안전하지만, 약간의 성능 저하가 있음
