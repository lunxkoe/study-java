# 프로세스와 스레드 소개

## 멀티태스킹과 멀티프로세싱

### 단일 프로그램 실행
- 프로그맹을 2개 이상 동시에 실행한다고 가정
- 연산을 처리할 수 있는 CPU 코어가 1개만 있다고 가정
- 동작
  - 프로그램 1을 CPU에서 처리
  - 프로그램 2를 CPU에서 처리
  - **즉, 순차적으로 처리**

- 이유
  - CPU 코어가 1개이므로, 한 번에 하나의 프로그램 코드만 실행할 수 있음

### 멀티태스킹
- 만약 CPU가 매우 빠르게 두 프로그램의 코드를 번갈아 수행한다면
- 사람이 느낄 때는 두 프로그램이 동시에 실행되는 것처럼 느껴짐

- 동작
  - Program 1 [1, 2, 3]
  - Program 2 [1, 2, 3]

  - CPU: Program 1 - 1
  - CPU: Program 2 - 1
  - CPU: Program 1 - 2
  - CPU: Program 2 - 2
  - CPU: Program 1 - 3
  - CPU: Program 2 - 3

- 프로그램의 실행 시간을 분할해서 동시에 실행되는 것처럼 하는 기법을 `시분할(Time Sharing, 시간 공유) 기법`이라고 함

### 참고
- CPU를 최대한 사용하면서 작업이 골고루 수행될 수 있게 최적화한다는 정도만 이해

### 멀티프로세싱
- CPU 코어가 둘 이상이면 어떻게 될까?
- 물리적으로 동시에 2개의 프로그램을 처리할 수 있음

- 개념
  - 컴퓨터 시스템에서 둘 이상의 프로세서를 사용하여 여러 작업을 동시에 처리하는 기술을 의미함

### 멀티프로세싱 vs 멀티태스킹
- 멀티프로세싱은 하드웨어 장비의 관점
- 멀티태스킹은 운영체제 소프트웨어 관점

- 멀티프로세싱
  - 여러 CPU를 사용하여 동시에 여러 작업을 수행하는 것을 의미함
  - 하드웨어 기반으로 성능을 향상
  - 다중 코어 프로세서

- 멀티태스킹
  - 단일 CPU가 여러 작업을 동시에 수행하는 것처럼 보이게 하는 것을 의미
  - 소프트웨어 기반으로 CPU 시간을 분할해서 사용

## 프로세스와 스레드

### 큰 그림
- 운영체제
  - 프로세스 A 
    - 코드, 힙, 기타
    - 스레드 A (스택)
  - 프로세스 B
    - 코드, 힙, 기타
    - 스레드 A (스택)
    - 스레드 B (스택)
    - 스레드 C (스택)

### 프로세스
- 프로그램은 실제 실행하기 전까지는 단순한 파일에 불과함
- 프로그램을 실행하면 프로세스가 만들어지고 프로그램이 실행됨
- 운영체제 안에서 실행 중인 프로그램을 프로세스라고 함
- 프로세스는 실행 중인 프로그램의 인스턴스
    
### 프로세스 특징
- 각 프로세스는 독립적인 메모리 공간을 갖고 있음
- 운영체제에서 별도의 작업 단위로 분리해서 관리됨
- 각 프로세스는 별도의 메모리 공간을 갖고 있기 때문에 서로 간섭하지 않음
- 하나의 프로세스가 충돌해도 다른 프로세스에는 영향을 미치지 않음

### 프로세스 구성
- 코드 섹션: 실행할 프로그램의 코드가 저장되는 부분
- 데이터 섹션: 전역 변수 및 정적 변수가 저장되는 부분
- 힙: 동적으로 할당되는 메모리 영역
- 스택: 함수 호출 시 생성되는 지역 변수나 반환 주소가 저장되는 영역

### 스레드
- 프로세스는 하나 이상의 스레드를 반드시 포함함

### 스레드 특징
- 프로세스 내에서 실행되는 작업의 단위
- 한 프로세스 내에서 여러 스레드가 존재할 수 있으며, 이들은 프로세스가 제공하는 동일한 메모리를 공유함
- 스레드는 프로세스보다 단순하므로 생성 및 관리가 단순하고 가벼움

### 스레드 구성
- 공유 메모리: 같은 프로세스의 코드, 데이터, 힙 섹션은 프로세스 안의 모든 스레드가 공유함
- 개별 스택: 각 스레드는 자신의 스택을 갖고 있음

### 프로그램이 실행된다는 것은 무슨 의미일까?
- 먼저 디스크에 있는 파일 덩어리인 프로그램을 메모리로 불러오면서 프로세스를 만듦
- 프로세스 안에 있는 코드가 한 줄 씩 실행되는 것
- 코드는 보통 main()부터 시작해서 하나씩 순서대로 내려가면서 실행됨

### 스레드의 수
- 단일 스레드: 한 프로세스 내에서 하나의 스레드만 존재
- 멀티 스레드: 한 프로세스 내에서 여러 스레드가 존재

### 멀티 스레드가 필요한 이유
- 하나의 프로그램도 그 안에서 동시에 여러 작업이 필요함
- 워드 프로그램 - 프로세스 A
  - 스레드 1: 문서 편집
  - 스레드 2: 자동 저장
  - 스레드 3: 맞춤법 검사

- 유튜브 - 프로세스 B
  - 스레드 1: 영상 재생
  - 스레드 2: 댓글 달기

## 스레드와 스케쥴링

### 상황
- CPU 코어 1개
- 프로세스 2개 (A, B)
  - A: 스레드 1개 (A)
  - B: 스레드 2개 (B, C)

### 동작
- 스레드 A1
- 스레드 B1
- 스레드 B2
- 스레드 C1
- 스레드 A2
- `위 과정을 반복`

### 단일 코어 스케쥴링
- `스케쥴링 큐(Queue)`: [스레드 B2, 스레드 A3, 스레드 C2]
- 큐에서 꺼내와서 CPU에서 연산을 순차적으로 수행함

### 멀티 코어 스케쥴링
- CPU 코어가 2개 이상이면 한 번에 많은 쓰레드를 물리적으로 진짜 동시에 실행할 수 있음
- `스케쥴링 큐(Queue)`: [스레드 B2, 스레드 A3, 스레드 C2]
  - CPU 1: [스레드 B2]
  - CPU 2: [스레드 A3]
  - `스케줄링 큐(Queue)`: [스레드 C2]

### 프로세스, 스레드, 스케쥴링 - 정리
- 멀티태스킹과 스케쥴링
  - 동시에 여러 작업을 수행하는 것처럼 보이는 것
  - 스케쥴링 기법을 사용함 (CPU 시간을 여러 작업에 나누어 배분)

- 프로세스
  - 실행 중인 프로그램의 인스턴스
  - 각 프로세스는 독립적인 메모리 공간을 가지고, 운영체제에서 독립된 실행 단위로 취급

- 스레드
  - 프로세스 내에서 실행되는 작은 단위
  - 여러 스레드는 하나의 프로세스 내에서 자원(코드, 데이터, 힙 섹션)을 공유함
  - 각 프로세스는 독립적인 스택을 가짐
  - **실제 CPU에 실행되는 단위는 스레드**

- 프로세스의 역할
  - 실행 환경을 제공함
  - 메모리 공간, 파일 핸들, 시스템 자원(네트워크 연결)
  - 프로세스 자체는 운영체제의 스케줄러에 의해 직접 실행되지 않으며, 프로세스 내의 스레드가 실행됨
  - 참고로 1개의 프로세스 안에 하나의 스레드만 실행되는 경우도 있고,
  - 1개의 프로세스 안에 여러 스레드가 실행되는 경우도 있음

## 컨텍스트 스위칭

### 멀티태스킹의 효율성
- 반드시 효율적인 것은 아님

### 컴퓨터의 멀티태스킹
- 스레드 A를 멈추는 시점에서 CPU에서 사용하던 값들을 메모리에 저장해두어야함
- 이후 스레드 A를 다시 실행할 때 이 값들을 CPU에 다시 불러와야함
- 이런 과정을 `Context Switching`이라고 함 - **비용이 발생함** -> 자주 한다고 좋은 것이 아님!!

### 효율성
- **멀티스레드는 대부분 효율적이지만, 컨텍스트 스위칭 과정이 필요하므로 항상 효율적인 것은 아님**

### 상황
- 1 ~ 10000까지 더해야 한다고 가정
    - 스레드 1: 1 ~ 5000까지 더함
    - 스레드 2: 5001 ~ 10000까지 더함
    - 마지막에 스레드 1의 결과와 스레드 2의 결과를 더함

- CPU 코어가 2개
  - 스레드 1 / 스레드 2로 나누어 병렬로 처리하는게 효율적임
  
- CPU 코어가 1개
  - 중간 중간에 컨텍스트 스위칭 비용이 발생함

### CPU 바운드 작업 vs I/O 바운드 작업
- CPU 바운드 작업
  - CPU의 연산 능력을 많이 요구하는 작업을 의미함
  - 이러한 작업은 주로 계산, 데이터 처리, 알고리즘 실행 등 CPU의 처리 속도가 완료 시간을 결정하는 경우
  - 예시: 복잡한 수학 연산, 데이터 분석, 비디오 인코딩, 과학적 시뮬레이션

- I/O 바운드 작업
  - 디스크, 네트워크, 파일 시스템 등과 같은 입출력 작업을 많이 요구하는 작업
  - I/O 작업이 완료될 때까지 대기 시간이 많이 발생, CPU는 상대적으로 대기 상태에 있는 경우가 많음
  - 쉽게 이야기해서 스레드가 CPU를 사용하지 않고, I/O 작업이 완료될 때까지 대기함
  - 예시: 데이터베이스 쿼리 처리, 파일 읽기/쓰기, 네트워크 통신, 사용자 입력 처리

### 웹 애플리케이션 서버
- 분야마다 다르지만, 실무에서는 CPU 바운드 작업보다는 I/O 바운드 작업이 많음
- 데이터베이스를 호출하고, 그 결과를 기다리는 등 기다리는 일이 많음
- 스레드가 CPU를 많이 사용하지 않는 I/O 바운드 작업이 많음

- 자바 웹 어플리케이션 서버의 경우 사용자의 요청 하나를 처리하는데 1개의 스레드가 필요함
- 4명이 동시에 요청하면 4개의 스레드가 작동함
- 이 경우 CPU 코어가 4개 있다고 해서 스레드 숫자도 4개로 설정하면, 4명의 사용자 요청만 처리할 수 있음
  - 한 요청당 CPU를 1%를 사용한다고 가정
- 단순히 생각해서 스레드 100개를 생성하면 100명의 요청을 처리할 수 있음

### 선택 기준
- CPU 바운드 작업: CPU 코어 수 + 1
  - CPU를 거의 100% 사용하는 작업이므로 스레드를 CPU 숫자에 최적화

- I/O 바운드 작업: CPU 코어 수보다 많은 스레드를 생성, CPU를 최대한 활용하는 숫자까지 스레드 생성
  - 성능 테스트를 통해 CPU를 최대한 활용하는 숫자까지 스레드 생성
  - 단, 너무 많은 스레드를 생성하면 컨텍스트 스위칭 비용도 함께 증가 - 적절한 성능 테스트 필요
