**# 스레드 제어와 생명 주기 2

## 인터럽트 - 시작 1

### 스레드 작업을 중간에 중단하기
```java
public class ThreadStopMainV1 {

    public static void main(String[] args) {
        MyTask task = new MyTask();
        Thread thread = new Thread(task, "work");
        thread.start();

        sleep(4000);
        log("작업 중단 지시 runFlag = false");
        task.runFlag = false;
    }

    static class MyTask implements Runnable {

        volatile boolean runFlag = true;

        @Override
        public void run() {
            while (runFlag) {
                log("작업 중");
                sleep(3000);
            }
            log("자원 정리");
            log("자원 종료");
        }
    }
}
```
- 실행 결과
    ```text
    20:57:57.362 [     work] 작업 중
    20:58:00.368 [     work] 작업 중
    20:58:01.347 [     main] 작업 중단 지시 runFlag = false
    20:58:03.371 [     work] 자원 정리
    20:58:03.373 [     work] 자원 종료
    ```
    - 특정 스레드의 작업을 중단하는 가장 쉬운 방법은 변수를 사용하는 것
    - runFlag를 사용해서 work 스레드에 작업 중단을 지시할 수 있음
    - 작업 하나에 3초가 걸린다고 가정하고, sleep(3000)을 사용
    - main 스레드는 4초 뒤에 작업 중단을 지시함
    - `volatile` 키워드는 여러 스레드에서 공유하는 값에 사용하는 키워드라고만 알아두기

- 문제
  - while 문 안에서 작업이 수행 중이라면 runFlag를 확인하는 시점까지 즉시 작업이 중단되지 않음

## 인터럽트 - 시작 2

### 특정 스레드 강제로 깨우거나 종료 시키기
- 인터럽트를 사용하면 waiting, timed_waiting 같은 대기 상태의 스레드를 직접 깨우서 작동하는 runnable 상태로 만들 수 있음

### 예제
```java
public class ThreadStopMainV2 {

    public static void main(String[] args) {
        MyTask task = new MyTask();
        Thread thread = new Thread(task, "work");
        thread.start();

        sleep(4000);
        log("작업 중단 지시 thread.interrupt()");
        thread.interrupt();
        log("work 스레드 인터럽트 상태1 = " + thread.isInterrupted());
    }

    static class MyTask implements Runnable {

        @Override
        public void run() {
            try {
                while (true) {
                    log("작업 중");
                    Thread.sleep(3000);
                }
            } catch (InterruptedException e) {
                log("work 스레드 인터럽트 상태2 = " + Thread.currentThread().isInterrupted());
                log("interrupt message = " + e.getMessage());
                log("state = " + Thread.currentThread().getState());
            }

            log("자원 정리");
            log("자원 종료");
        }
    }
}
```
- 실행 결과
    ```text
    21:14:04.815 [     work] 작업 중
    21:14:07.834 [     work] 작업 중
    21:14:08.800 [     main] 작업 중단 지시 thread.interrupt()
    21:14:08.800 [     main] work 스레드 인터럽트 상태1 = true
    21:14:08.800 [     work] work 스레드 인터럽트 상태2 = false
    21:14:08.801 [     work] interrupt message = sleep interrupted
    21:14:08.802 [     work] state = RUNNABLE
    21:14:08.802 [     work] 자원 정리
    21:14:08.802 [     work] 자원 종료
    ```
  - 인터럽트를 딱 받은 순간에는 true
  - 인터럽트를 받고 깨워난 경우에는 false
  - 깨어나서 runnable 상태가 됨
  - 인터럽트를 호출하는 즉시 바로 깨어나는 것이 아님
    - Thread.sleep() 같은 걸 만나면 InterruptedException이 발생함
    - 즉, InterruptedException을 던지는 메서드를 호출하거나 또는 호출하며 대기 중일 때 발생함

- 참고로 스레드가 runnable 상태여야 catch의 예외 코드도 실행될 수 있음

## 인터럽트 - 시작 3

### 인터럽트를 체크하는 부분
- InterruptedException을 던지는 메서드를 호출하거나 또는 호출하며 대기 중이 때만 발생함
- while이 시작되는 부분에서도 체크할 수 있도록 할 수 없을까?
- **인터럽트 상태를 확인하면 더 빨리 반응할 수 있음**

### 예제
```java
public class ThreadStopMainV3 {

    public static void main(String[] args) {
        MyTask task = new MyTask();
        Thread thread = new Thread(task, "work");
        thread.start();

        sleep(100);
        log("작업 중단 지시 thread.interrupt()");
        thread.interrupt();
        log("work 스레드 인터럽트 상태1 = " + thread.isInterrupted());
    }

    static class MyTask implements Runnable {

        @Override
        public void run() {

            while (!Thread.currentThread().isInterrupted()) { // 인터럽트 상태 확인만 / 변경 X
                log("작업 중");
            }
            log("work 스레드 인터럽트 상태2 = " + Thread.currentThread().isInterrupted());

            log("자원 정리");
            log("자원 종료");
        }
    }
}
```

    ```text
    21:37:40.024 [     work] 작업 중
    ```

    - 하지만 지금은 true인 상태를 계속해서 가지고 있음 (work 스레드 인터럽트 상태2 = true)

### 왜 예외를 받으면 false로 바꿀까?

### 주요 실행 순서
- main 스레드는 interrupt() 메서드를 통해서 work 스레드에 인터럽트를 걸음
- work 스레드는 인터럽트 상태가 됨 = true
  - while의 조건이 false가 되면서 반복문을 탈출함
  - **하지만 여기 코드에서는 심각한 문제가 있음**
    - 인터럽트 상태가 true로 계속 유지된다는 문제가 있음

### 왜 문제가 있는 것일까?
- 상황: 자원 정리를 하는 곳에서 InterruptedException을 던지는 메소드를 실행해야한다면
  - true로 유지되어있기 때문에 인터럽트 예외가 발생하게 됨
  - 정상적으로 자원 정리를 할 수 없게 됨
  - 기대한 의도: while 문에서만 빠져나가길 기대함 => 여기까지는 기대데로 동작함
    - 문제는 Thread.sleep()에서 true 때문에 자원 정리가 정상적으로 이루어지지 않고, 예외가 발생함

- **이러한 이유로 인터럽트 예외가 터지면 인터럽트 상태를 false로 돌아오는 이유**

## 인터럽트 - 시작 4

### Thread.isInterrupted() => Thread.interrupted()
- 스레드의 인터럽트 상태를 단순히 확인만 하는 용도라면 isInterrupted()를 사용하면 됨
- 하지만 직접 확인해서 사용할 때는 Thread.interrupted()를 사용해야함
  - 스레드가 인터럽트 상태라면 true를 반환하고 해당 인터럽트 상태를 false로 변경함
  - 스레드가 인터럽트 상태가 아니라면 false를 반환하고 변경하지 않음

### 예제
```java
public class ThreadStopMainV4 {

    public static void main(String[] args) {
        MyTask task = new MyTask();
        Thread thread = new Thread(task, "work");
        thread.start();

        sleep(100);
        log("작업 중단 지시 thread.interrupt()");
        thread.interrupt();
        log("work 스레드 인터럽트 상태1 = " + thread.isInterrupted());
    }

    static class MyTask implements Runnable {

        @Override
        public void run() {

            while (!Thread.interrupted()) { // 인터럽트 상태 확인만 / 변경 X
                log("작업 중");
            }
            log("work 스레드 인터럽트 상태2 = " + Thread.currentThread().isInterrupted());

            try {
                log("자원 정리");
                Thread.sleep(1000);
                log("자원 종료");
            } catch (InterruptedException e) {
                log("자원 정리 실패 - 자원 정리 중 인터럽트 발생");
                log("work 스레드 인터럽트 상태3 = " + Thread.currentThread().isInterrupted());
            }
        }
    }
}
```
- 실행 결과
    ```text

    21:48:17.875 [     work] 작업 중
    21:48:17.875 [     work] 작업 중
    21:48:17.875 [     work] 작업 중
    21:48:17.875 [     work] 작업 중
    21:48:17.876 [     work] 작업 중
    21:48:17.876 [     main] 작업 중단 지시 thread.interrupt()
    21:48:17.876 [     work] 작업 중
    21:48:17.877 [     work] work 스레드 인터럽트 상태2 = false
    21:48:17.877 [     main] work 스레드 인터럽트 상태1 = true
    21:48:17.877 [     work] 자원 정리

    ```
    - 이제 자원 정리가 정상적으로 완료됨을 확인할 수 있음

### 정리
- 자바는 인터럽트 예외가 한 번 발생하면, 스레드의 인터럽트 상태를 다시 정상으로 돌림
- 스레드의 인터럽트 상태를 정상으로 돌리지 않으면 이후에도 계속 인터럽트가 발생하게 됨
- 인터럽트의 목적을 달성하면 **다시 정상으로 돌려두어야 이후 작업에서 문제가 생기지 않음**

- 주의: 정답은 아님 => 상황: 자원 정리도 하지 않고, 빠르게 종료해야한다면 스레드를 다시 인터럽트 상태로 변경하는 것도 방법임**
    - thread.stop()은 절대 사용하면 안됨 (삭제된 기능)

## 프린터 예제 - 시작

### 프린터
- 사용자의 입력을 프린터에 출력하는 간단한 예제

### 예제
```java
public class MyPrinterV1 {

    public static void main(String[] args) {
        Printer printer = new Printer();
        Thread printerThread = new Thread(printer);
        printerThread.start();

        Scanner userInput = new Scanner(System.in);
        while (true) {
            log("프린터할 문서를 입력하세요. 종료 (q): ");
            String input = userInput.next();
            if (input.equals("q")) {
                printer.work = false;
                break;
            }

            printer.addJob(input);
        }
    }

    static class Printer implements Runnable {

        volatile boolean work = true;
        Queue<String> jobQueue = new ConcurrentLinkedQueue<>();

        @Override
        public void run() {
            while (work) {
                if (jobQueue.isEmpty()) {
                    continue;
                }

                String job = jobQueue.poll();
                log("출력 시작: " + job + ", 대기 문서: " + jobQueue);
                sleep(3000);
                log("출력 완료");
            }

            log("프린터 종료");
        }

        public void addJob(String input) {
            jobQueue.offer(input);
        }
    }
}
```
- volatile: 여러 스레드가 동시에 접근하는 변수에는 volatile 키워드를 붙여주어야함
- 여기서는 main 스레드 printer 스레드 둘 다 work 변수에 동시에 접근할 수 있음
- ConcurrentLinkedQueue: 여러 스레드가 동시에 접근하는 경우, 일반적인 자료 구조를 사용하면 안됨

## 프린터 예제 - 인터럽트 도입

### 코드
```java
public class MyPrinterV2 {

    public static void main(String[] args) {
        Printer printer = new Printer();
        Thread printerThread = new Thread(printer);
        printerThread.start();

        Scanner userInput = new Scanner(System.in);
        while (true) {
            log("프린터할 문서를 입력하세요. 종료 (q): ");
            String input = userInput.next();
            if (input.equals("q")) {
                printerThread.interrupt();
                break;
            }

            printer.addJob(input);
        }
    }

    static class Printer implements Runnable {

        Queue<String> jobQueue = new ConcurrentLinkedQueue<>();

        @Override
        public void run() {
            while (!Thread.interrupted()) {
                if (jobQueue.isEmpty()) {
                    continue;
                }

                String job = jobQueue.poll();
                log("출력 시작: " + job + ", 대기 문서: " + jobQueue);
                try {
                    Thread.sleep(3000);
                } catch (InterruptedException e) {
                    log("인터럽트!");
                    break;
                }
                log("출력 완료");
            }

            log("프린터 종료");
        }

        public void addJob(String input) {
            jobQueue.offer(input);
        }
    }
}
```
- interrupt(): sleep() 상태에서 빠져나옴
- work = false: while 문을 체크하는 곳에서 빠져나옴

## yield 양보하기

### 필요한 이유
- 어떤 스레드를 얼마나 실행할지는 운영체제가 스케줄링을 통해 결정함
- 특정 스레드가 크게 바쁘지 않은 상황이여서 다른 스레드에 CPU 실행 기회를 양보할 수 있음
- 이렇게 양보하면 스케줄링 큐에 대기 중인 다른 스레드가 CPU 실행 기회를 더 빨리 얻을 수 있음

### 예제
```java
public class YieldMain {

    static final int THREAD_COUNT = 1000;

    public static void main(String[] args) {
        for (int i = 0; i < THREAD_COUNT; i++) {
            Thread thread = new Thread(new MyRunnable());
            thread.start();
        }
    }

    static class MyRunnable implements Runnable {

        @Override
        public void run() {
            for (int i = 0; i < 10; i++) {
                System.out.println(Thread.currentThread().getName() + " - " + i);
//                 1. empty
//                 sleep(1); // 2. sleep
                 Thread.yield(); // 3. yield
            }
        }
    }
}
```
- sleep(1)
  - runnable -> timed_waiting으로 변경됨
  - 실행 스케줄링에서 잠시 제외됨
  - 단점: runnable -> timed_waiting -> runnable로 변경되는 복잡한 과정을 거침
    - 또한 특정 시간 동안 스레드가 실행되지 않는 단점이 있음
    - 쉽게 말해서 양보할 사람이 없는데, 혼자서 양보한 이상한 상황이 될 수도 있음

- yield()
  - runnable 상태는 크게 두 가지로 나눌 수 있음
    - running: 스레드가 CPU에서 실제로 실행 중인 상태
    - ready: 스레드가 실행될 준비가 되었지만, CPU가 바빠서 스케줄링 큐에서 대기 중인 상태
    - **참고로 자바에서는 두 상태를 구분할 수 없음**

  - Thread.yield() 메서드는 현재 실행 중인 스레드가 자발적으로 CPU를 양보하여 다른 스레드가 실행될 수 있도록 함
  - yield() 메서드를 호출한 스레드는 Runnable 상태를 유지하면서 CPU를 양보함
  - 즉, 다시 스케쥴링 큐에 들어가면서 다른 스레드에게 CPU 사용 기회를 넘김
  - 반드시 다른 스레드에게 넘기는 것은 아님

```java
while (!Thread.interrupted()) {

    }
```
- 이전 체크 로직에 CPU 자원을 많이 사용하게 되면, 정작 필요한 스레드들의 효율이 상대적으로 떨어질 수 있음
- 다른 스레드에게 양보하는게 전체 관점에서 더 효율적임
