# 스레드 제어와 생명 주기 1

## 스레드 기본 정보

### main 스레드와 custom 스레드
```java
public class ThreadInfoMain {

    public static void main(String[] args) {
        // main 스레드
        Thread mainThread = Thread.currentThread();
        log("mainThread = " + mainThread);
        log("mainThread.threadId() = " + mainThread.threadId());
        log("mainThread.getName() = " + mainThread.getName());
        log("mainThread.getPriority() = " + mainThread.getPriority());
        log("mainThread.getThreadGroup() = " + mainThread.getThreadGroup());
        log("mainThread.getState() = " + mainThread.getState());

        // myThread 스레드
        Thread myThread = new Thread(new HelloRunnable(), "myThread");
        log("myThread = " + myThread);
        log("myThread.threadId() = " + myThread.threadId());
        log("myThread.getName() = " + myThread.getName());
        log("myThread.getPriority() = " + myThread.getPriority());
        log("myThread.getThreadGroup() = " + myThread.getThreadGroup());
        log("myThread.getState() = " + myThread.getState());
    }
}
```

### 스레드 객체 정보
- 스레드: [스레드ID, 스레드 이름, 우선순위, 스레드 그룹]
- 스레드ID
  - 스레드의 고유 식별자를 반환하는 메서드
  - ID는 JVM 내에서 각 스레드에 대해 유일함
  - ID는 스레드가 생성될 때 할당되며, 직접 지정할 수 없음

- 스레드 이름
  - 중복이 될 수 있음

- 스레드 우선순위
  - 자주 실행되는 정도
  - 1 ~ 10 (기본값 5)
  - 낮을 수록 우선순위가 낮음
  - 절대적인 것이 아닌 힌트만 주는 것

- 스레드 그룹
  - 스레드가 속한 스레드 그룹을 반환
  - 기본적으로 모든 스레드는 부모 스레드와 동일한 스레드 그룹에 속하게 됨
  - 부모 스레드
    - 새로운 스레드를 생성하는 스레드를 의미
    - myThread의 부모는 mainThread
  - 참고: 잘 사용하지 않기 때문에 이런 것이 있구나 정도로만 넘어가자

- 스레드 상태
  - NEW: 스레드가 아직 시작되지 않은 상태
  - RUNNABLE: 스레드가 실행 중이거나 실행될 준비가 된 상태
  - BLOCKED: 스레드가 동기화 락을 기다리는 상태
  - WAITING: 스레드가 다른 스레드의 특정 작업이 완료되기를 기다리는 상태
  - TIMED_WAITING: 일정 시간동안 기다리는 상태
  - TERMINATED: 스레드가 실행을 마친 상태

## 스레드의 생명 주기 - 설명

### 스레드의 생명 주기
- New

- Runnable
  - Blocked
  - Waiting
  - Timed WAITING
  
- Terminate

- 일시 중지 상태라는 것은 없음 (CPU를 거의 사용하지 않고 기다리는 상태라는 의미)

### 자세히
- New (새로운 상태)
  - 스레드가 생성되고 아직 시작되지 않은 상태
  - Thread 객체가 생성되지만, start() 메서드가 호출되지 않은 상태

- Runnable (실행 가능 상태)
  - 스레드가 실행될 준비가 된 상태
  - start() 메서드가 호출되면 이 상태로 들어감
  - 모든 스레드가 동시에 실행되는 것이 아니라 스케줄러에 따라서 CPU에서 실행될 수 있는 상태
  - 대기열에 있는 CPU에서 실행되고 있든 모둔 Runnable 상태

- Blocked (차단 상태)
  - 스레드가 다른 스레드에 의해 동기화 락을 얻기 위해 기다리는 상태
  - synchronized (lock) { .. } 코드 블록에 진입하려고 할 때, 다른 스레드가 lock을 가지고 있는 경우

- Waiting (대기 상태)
  - 스레드가 다른 스레드의 특정 작업이 완료되기를 무기한 기다리는 상태
  - wait(), join() 메서드가 호출될 때 이 상태가 됨
  - 다른 스레드가 notify() 또는 notifyAll() 메서드를 호출하거나, join()이 완료될 때까지 기다림
  - object.wait()

- Timed Waiting (시간 제한 대기 상태)
  - 특정 시간 동안 다른 스레드의 작업이 완료되기를 기다리는 상태
  - sleep(long mills), wait(long timeout), join(long millis) 메서드가 호출될 때 이 상태가 됨
  - Thread.sleep(1000)

- Terminated (종료 상태)
  - 스레드의 실행이 완료된 상태
  - 스레드가 정상적으로 종료되거나, 예외가 발생하여 종료된 경우 이 상태로 들어감
  - 스레드는 한 번 종료되면 다시 시작할 수 없음

## 스레드의 생명 주기 - 코드

### 예제
```java
public class ThreadStateMain {

    public static void main(String[] args) throws InterruptedException {
        Thread thread = new Thread(new MyRunnable());
        log("myThread.state1 = " + thread.getState());
        log("myThread.start()");
        thread.start();
        Thread.sleep(1000);
        log("myThread.state3 = " + thread.getState());
        Thread.sleep(4000);
        log("myThread.state4 = " + thread.getState());
    }

    static class MyRunnable implements Runnable {

        @Override
        public void run() {
            log("start");
            log("myThread.state2 = " + Thread.currentThread().getState());
            log("sleep() start");
            try {
                Thread.sleep(3000);
                log("sleep() end");
                log("myThread.state4 = " + Thread.currentThread().getState());
            } catch (InterruptedException e) {
                throw new RuntimeException(e);
            }
        }
    }
}
```

- 실행 결과
  ```text

    18:50:27.421 [ Thread-0] sleep() start
    ```

### Runnable 인터페이스
```java
public interface Runnable {
    void run();
}
```
- 자바에서 메서드 재정의 할 때, 메서드가 지켜야할 예외와 관련된 규칙이 있음
  - 체크 예외
    - 부모 메서드가 체크 예외를 던지지 않을 경우, 재정의된 자식 메서드도 체크 예외를 던질 수 없음
    - 자식 메서드는 부모 메서드가 던질 수 있는 체크 예외의 하위 타입만 던질 수 있음
  - 언체크(런타임) 예외
    - 예외 처리를 강제하지 않으므로 다 던질 수 있음

### 왜 이런 제약을 두는 걸까?
- 개발의 안전성을 위해서 제약을 둚
- 체크 예외라는 건 터지면 반드시 잡아서 처리해야하는데, 부모 메서드와 자식 메서드의 체크 예외 타입이 달라지면 문제가 발생할 수 있음

### 체크 예외를 run() 메서드에서 던질 수 없도록 강제하는 이유
- 체크 예외를 run() 메서드에서 던질 수 없도록 강제를 함으로써 개발자는 반드시 try-catch를 블록 내에서 처리하게 됨
- 예외 발생 시 예외가 적절히 처리되지 않아서 프로그램이 비정상 종료되는 상황을 방지할 수 있음
- 멀티스레딩 환경에서는 스레드의 안정성과 일관성을 유지할 수 있음
- `최근에는 체크 예외보다는 런타임 예외를 선호함`
  - **Runnable 개선된 버전 Callable**

### 참고 사항
- Thread.sleep()
- Thread.currentThread().sleep()
- 둘 다 이 코드를 실행하는 스레드를 sleep() 시킴
  - 다른 스레드를 ThreadObject.sleep()을 한다고, 해당 스레드가 sleep()이 되는 것이 절대 아님에 주의

## join - 필요한 상황

### 1 ~ 100까지 더하는 코드
```java
public class JoinMainV1 {

    public static void main(String[] args) {
        log("start");

        SumTask sumTask1 = new SumTask(1, 50);
        SumTask sumTask2 = new SumTask(51, 100);

        Thread thread1 = new Thread(sumTask1);
        Thread thread2 = new Thread(sumTask2);

        thread1.start();
        thread2.start();

        log("task1.result = " + sumTask1.result);
        log("task2.result = " + sumTask2.result);

        int sumAll = sumTask1.result + sumTask2.result;
        log("sumAll = " + sumAll);

        log("end");
    }

    static class SumTask implements Runnable {

        int startValue;
        int endValue;
        int result = 0;

        public SumTask(int startValue, int endValue) {
            this.startValue = startValue;
            this.endValue = endValue;
        }

        @Override
        public void run() {
            log("작업 시작");

            sleep(2000);
            int sum = 0;
            for (int i = startValue; i <= endValue; i++) {
                sum += i;
            }
            result = sum;

            log("작업 완료 result = " + result);
        }
    }
}
```

  - main이 먼저 종료되어서 작업이 완료 되기 전에 상태를 읽고 종료되어서 main에는 정상적이 값이 반영이 되지 않은 것을 확인할 수 있음
  - **주의: 무조건은 아님** (현재 상태에서 실행 순서는 100% 보장되지 않음)

### 참고 - this의 비밀
- 어떤 메서드를 호출하는 것은 정확히는 특정 스레드가 어떤 메서드를 호출하는 것
- 메서드 단위로 스택 프레임을 만들고, 해당 스택 프레임을 스택 위에 쌓아 올림
- 이때 인스턴스의 메서드를 호출하면, 어떤 인스턴스의 메서드를 호출했는지 기억하기 위해서 
- 해당 인스턴스의 참조값을 스택 프레임 내에 저장해둠 => **이것이 this**

## join - join 사용

### 예제
```java
public class JoinMainV3 {

    public static void main(String[] args) throws InterruptedException {
        log("start");

        SumTask task1 = new SumTask(1, 50);
        SumTask task2 = new SumTask(51, 100);

        Thread thread1 = new Thread(task1);
        Thread thread2 = new Thread(task2);

        thread1.start();
        thread2.start();

        // 스레드가 종료될 때까지 대기
        log("join() - main 스레드가 thread1, thread2 종료까지 대기");
        thread1.join(); // 스레드 1이 종료될 때까지 대기
        thread2.join(); // 스레드 2가 종료될 때까지 대기
        log("main 스레드 대기 완료");

        log("task1.result = " + task1.result);
        log("task2.result = " + task2.result);

        int sumAll = task1.result + task2.result;
        log("sumAll = " + sumAll);

        log("end");
    }

    static class SumTask implements Runnable {

        int startValue;
        int endValue;
        int result = 0;

        public SumTask(int startValue, int endValue) {
            this.startValue = startValue;
            this.endValue = endValue;
        }

        @Override
        public void run() {
            log("작업 시작");

            sleep(2000);
            int sum = 0;
            for (int i = startValue; i <= endValue; i++) {
                sum += i;
            }
            result = sum;

            log("작업 완료 result = " + result);
        }
    }
}
```
- 실행 결과
  ```text
  20:09:58.195 [     main] start
  20:09:58.200 [     main] join() - main 스레드가 thread1, thread2 종료까지 대기
  20:09:58.200 [ Thread-0] 작업 시작
  20:09:58.201 [ Thread-1] 작업 시작
  20:10:00.216 [ Thread-1] 작업 완료 result = 3775
  20:10:00.216 [ Thread-0] 작업 완료 result = 1275
  20:10:00.218 [     main] main 스레드 대기 완료
  20:10:00.220 [     main] task1.result = 1275
  20:10:00.221 [     main] task2.result = 3775
  20:10:00.221 [     main] sumAll = 5050
  20:10:00.223 [     main] end
  ```
  - 시간을 잘 보면 작업이 완료되자마자 main 스레드 대기 완료가 뜨는 것을 볼 수 있음

- 동작
  - thread1.join(): main 스레드가 waiting 상태로 들어감
  - thread1이 작업을 완료하고 main 스레드가 runnable 상태로 들어감
  - thread2.join(): main 스레드가 waiting 상태로 들어감
  - thread2가 작업을 완료하고 main 스레드가 runnable 상태로 들어감
    - thread2가 terminated 상태면 waiting 상태로 들어가지 않고, 바로 빠져나옴

### join()의 단점
- 특정 스레드가 완료될 때까지 무기한 기다려야한다는 단점이 있음
- 특정 스레드가 무조건 완료될 때까지 기다려야하면 join()을 사용
- 하지만 일정 시간 동안만 기다리고 싶다면 어떻게 해야할까? -> timed waiting 상태

## join - 특정 시간만큼만 대기

### join 두 종류
- join(): 호출 스레드는 대상 스레드가 완료될 때까지 무한정 대기함
- join(ms): 호출 스레드는 특정 시간만큼만 대기함. 호출 스레드는 지정한 시간이 지나면 다시 RUNNABLE 상태가 됨

### 예제
```java
public class JoinMainV4 {

    public static void main(String[] args) throws InterruptedException {
        log("start");

        SumTask task1 = new SumTask(1, 50);

        Thread thread1 = new Thread(task1);

        thread1.start();

        // 스레드가 종료될 때까지 대기
        log("join() - main 스레드가 thread1, thread2 종료까지 대기");
        thread1.join(1000); // 스레드 1이 종료될 때까지 1초만 기다림
        log("main 스레드 대기 완료");

        log("task1.result = " + task1.result);

        int sumAll = task1.result;
        log("sumAll = " + sumAll);

        log("end");
    }

    static class SumTask implements Runnable {

        int startValue;
        int endValue;
        int result = 0;

        public SumTask(int startValue, int endValue) {
            this.startValue = startValue;
            this.endValue = endValue;
        }

        @Override
        public void run() {
            log("작업 시작");

            sleep(2000);
            int sum = 0;
            for (int i = startValue; i <= endValue; i++) {
                sum += i;
            }
            result = sum;

            log("작업 완료 result = " + result);
        }
    }
}
```

  ```text

  20:30:09.914 [     main] main 스레드 대기 완료
  ```

  - 시간을 보면 1초 정도만 기다리는 것을 확인할 수 있음

### 정리
- 다른 스레드가 끝날 때까지 무한정 기다려야 한다면 join()을 사용하고, 다른 스레드의 작업을 무한정 기다릴 수 없다면 join(ms)를 사용하면 됨
- 기다리다 중간에 나오는 상황인데, 결과가 없다면 추가적인 오류 처리가 필요함
