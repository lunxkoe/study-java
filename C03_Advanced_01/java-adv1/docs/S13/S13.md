# 스레드 풀과 Executor 프레임워크 1

## 스레드를 직접 사용할 때의 문제점

### 실무에서 발생할 수 있는 문제점
- 스레드 생성 시간으로 인한 성능 문제
- 스레드 관리 문제
- Runnable 인터페이스의 불편함

### 스레드 생성 비용으로 인한 성능 문제
- 메모리 할당
  - 각 스레드는 자신만의 호출 스택을 가지고 있어야 함
  - 호출 스택은 스레드가 실행되는 동안 사용하는 메모리 공간
  - 스레드를 생성할 때는 이 호출 스택을 위한 메모리를 할당해야 함

- 운영체제 자원 사용
  - 스레드를 생성하는 작업은 운영체제 커널 수준에서 이루어짐
  - 시스템 콜을 통해 처리됨
  - 이는 CPU와 메모리 리소스를 소모하는 작업

- 참고로 스레드 하나는 보통 1MB 이상의 메모리를 사용 (스택 메모리 크기)
- 작업 실행보다 스레드의 생성 시간이 더 오래 걸릴 수 있음
- **생성한 스레드를 재사용하는 방법을 고려할 수 있음**

### 스레드 관리 문제
- 서버의 CPU, 메모리 자원은 한정되어 있기 때문에 스레드는 무한하게 만들 수 없음
- 요청 하나 당 하나의 스레드를 할당해준다고 할 때, 갑자기 1만개 스레드가 필요하다면?
- 시스템이 버틸 수 있는 최대 스레드의 수까지만 스레드를 생성할 수 있게 관리해야함

### Runnable 인터페이스의 불편함
- 반환 값이 없음으로 스레드의 실행 결과를 직접 받을 수 없음
- 예외 처리: run() 메소드는 체크 예외를 던질 수 없음

### 해결
- 스레드 풀: 스레드를 생성하고 관리하는 풀(Pool)
  - 스레드는 스레드 풀에서 대기
  - 작업 요청이 옴
  - 스레드 풀에서 이미 만들어진 스레드 하나를 조회
  - 조회한 스레드 1로 작업을 처리
  - 스레드 1은 작업을 완료
  - 작업을 완료한 스레드는 종료되는 것이 아니라, 다시 스레드 풀에 반납 (이후 재사용)

- 컬렉션에 스레드를 보관하고 재사용할 수 있게 하면 됨
- 하지만, 스레드 풀에 있는 스레드는 처리할 작업이 없다면, 대기(Waiting) 상태로 관리하고, 작업 요청이 오면 Runnable 상태로 변경

### 자바의 해결책
- Executor 프레임워크

## Executor 프레임워크 소개

### Executor 프레임워크
- 멀티스레딩 및 병렬 처리를 쉽게 사용할 수 있도록 돕는 기능의 모음
- 작업 실행의 관리 및 스레드 풀 관리를 효율적으로 처리해서 직접 스레드를 생성하고 관리하는 복잡함을 줄여줌
- Executor 인터페이스
```java
public interface Executor {
    void execute(Runnable command);
}
```

- ExecutorService 인터페이스
```java
public interface ExecutorService extends Executor, AutoCloseable {
    <T> Future<T> submit(Callable<T> task);
    
    @Override
    default void close() {...}
    
    ...
}
```
- Executor 인터페이스를 확장해서 작업 제출과 제어 기능을 추가로 제공함
- 주요 메서드 `submit()`, `close()`가 있음
- Executor 프레임워크를 사용할 때는 대부분 이 인터페이스를 사용함
- 주요 구현체: `ThreadPoolExecutor`

### 로그 출력 유틸리티 만들기
```java
public abstract class ExecutorUtils {

    public static void printState(ExecutorService executorService) {
        if (executorService instanceof ThreadPoolExecutor poolExecutor) {
            int pool = poolExecutor.getPoolSize();
            int active = poolExecutor.getActiveCount();
            int queuedTasks = poolExecutor.getQueue().size();
            long completedTask = poolExecutor.getCompletedTaskCount();
            log("[pool=" + pool + ", active=" + active + ", queuedTasks=" + queuedTasks +
                    ", completedTask=" + completedTask + "]");
        } else {
            log(executorService);
        }
    }
}
```
- ThreadPoolExecutor가 더 많은 기능을 제공하기 때문에 다운 캐스팅을 해서 사용
- .getPoolSize(): 스레드 풀에서 관리되는 스레드의 숫자
- .getActiveCount(): 작업을 수행하는 스레드의 숫자
- .getQueue().size(): 큐에 대기중인 작업의 숫자
- .getCompletedTaskCount(): 완료된 작업의 숫자

## ExecutorService 코드로 시작하기

### 1초간 대기하는 간단한 작업
```java
public class RunnableTask implements Runnable {

    private final String name;
    private int sleepMs = 1000;

    public RunnableTask(String name) {
        this.name = name;
    }

    public RunnableTask(String name, int sleepMs) {
        this.name = name;
        this.sleepMs = sleepMs;
    }

    @Override
    public void run() {
        log(name + " 시작");
        sleep(sleepMs); // 작업 시간
        log(name + " 완료");
    }
}
```

```java
public class ExecutorBasicMain {

    public static void main(String[] args) {
        ExecutorService es = new ThreadPoolExecutor(
                2,
                2,
                0,
                TimeUnit.MILLISECONDS,
                new LinkedBlockingQueue<>()
        );

        log("== 초기 상태 ==");
        printState(es);
        es.execute(new RunnableTask("taskA")); // corePoolSize까지는 쓰레드를 만들고
        es.execute(new RunnableTask("taskB")); // corePoolSize까지는 쓰레드를 만들고
        es.execute(new RunnableTask("taskC")); // 여기서부터는 쓰레드를 만들지 않고, 재사용
        es.execute(new RunnableTask("taskD"));
        es.execute(new RunnableTask("taskE"));
        log("== 작업 수행 중 ==");
        printState(es);

        sleep(5000);
        printState(es);

        es.close();
        log("== shutdown ==");
        printState(es);
    }
}
```

### ThreadPoolExecutor 생성자
- corePoolSize: 스레드 풀에서 관리되는 기본 스레드의 수
  - 맨 처음 스레드 풀이 생성될 때는 0개로 시작
  - corePoolSize 개수까지의 작업이 들어올 때가지는 새로 생성
- maximumPoolSize: 스레드 풀에서 관리되는 최대 스레드 수
- keepAliveTime, TimeUnit unit: 기본 스레드 수를 초과해서 만들어진 스레드가 생존할 수 있는 대기 시간, 이 시간이 동안 처리할 작업이 없다면 초과 스레드는 제거됨
- BlockingQueue workQueue: 작업을 보관할 블로킹 큐

## Runnable의 불편함

### Runnable 인터페이스의 불편함
- 반환 값이 없음
- 예외 처리

### Runnable로 계산 결과 받아오기

```java
public class RunnableMain {
```

## Future 1 - 시작

### Callable
```java
public interface Callable<V> {
    V call() throws Exception;
}
```
- 반환타입이 제네릭 - 값을 반환할 수 있음
- throws Exception 예외가 선언되어있음 - 예외를 던질 수 있음

### 예제 코드
```java
public class CallableMainV1 {

    public static void main(String[] args) throws ExecutionException, InterruptedException {
        ExecutorService es = Executors.newFixedThreadPool(1);// 풀이 하나만 있는 것
        Future<Integer> future = es.submit(new MyCallable());
        Integer result = future.get();
        log("result value = " + result);
        es.close();
    }

    static class MyCallable implements Callable<Integer> {

        @Override
        public Integer call() throws Exception {
            log("Callable 시작");
            sleep(2000);
            int value = new Random().nextInt(10);
            log("create value = " + value);
            log("Callable 완료");
            return value;
        }
    }
}
```
- 실행 결과
  ```text
  13:52:16.250 [pool-1-thread-1] Callable 시작
  13:52:18.256 [pool-1-thread-1] create value = 9
  13:52:18.257 [pool-1-thread-1] Callable 완료
  13:52:18.259 [     main] result value = 9
  ```
  - newFixedThreadPool(size)를 사용하면 편리하게 ExecutorService를 생성할 수 있음
  - Executors.newFixedThreadPool(1) == new ThreadpoolExecutor(1, 1, 0, TimeUnit.MILLISECONDS, new LinkedBlockingQueue<>())
  - 작업의 처리 결과가 직접 반환되는 것이 아니라, Future라는 인터페이스로 반환됨

### Executor 사용의 장점
- 요청 스레드의 결과를 받아야하는 상황이라면
- Callable을 사용한 방식은 Runnable을 사용하는 방식보다 훨신 편리함
- 단순한 싱글스레드 방식으로 개발하는 느낌이 듦
- 그냥 작업을 던지고 받으면 됨

### 조금 더 나아간 이해
- 기반 원리를 제대로 이해해야 문제없이 사용할 수 있음
- future.get()을 호출하는 메인 스레드는 future.get()을 호출했을때 2가지 상황으로 나뉘게 됨
  - MyCallable 작업을 처리하는 스레드 풀의 스레드가 작업을 완료했음
  - MyCallable 작업을 처리하는 스레드 풀의 스레드가 아직 작업을 완료하지 못했음

## Future 2 - 분석

### Future
- 미래라는 의미 / 누구의 미래를 의미하는 것일까?

- submit()의 호출로 MyCallable의 인스턴스를 전달함
- 이때 submit()은 MyCallable.call()이 반환하는 무작위 숫자 대신 Future를 반환함
- 생각해보면 MyCallable이 즉시 실행되어서 즉시 결과를 반환하는 것은 불가능함
  - 스레드 풀의 스레드가 미래의 어떤 시점에 이 코드를 대신 실행해야함
- MyCallable.call() 메서드는 호출 스레드가 실행하는 것도 아니고, 스레드 풀의 다른 스레드가 실행하기 때문에 언제 실행이 완료되어서 결과를 반환할 지 알 수 없음
- 따라서 결과를 즉시 반환받는 것은 불가능함
- es.submit()은 MyCallable의 결과를 반환하는 대신에 Future라는 객체를 대신 제공함
- 정리하면 Future는 전달한 작업의 미래임
  - 이 객체를 통해 전달한 작업의 미래 결과를 받을 수 있음

### Future의 동작
```java
public class CallableMainV2 {

    public static void main(String[] args) throws ExecutionException, InterruptedException {
        ExecutorService es = Executors.newFixedThreadPool(1);// 풀이 하나만 있는 것
        log("submit() 호출");
        Future<Integer> future = es.submit(new MyCallable());
        log("future 즉시 반환, future = " + future);

        log("future.get() [블로킹] 메서드 호출 시작 -> main 스레드 WAITING");
        Integer result = future.get(); // 결과가 나올 때까지 기다림
        log("future.get() [블로킹] 메서드 호출 완료 -> main 스레드 RUNNABLE");

        log("result value = " + result);
        log("future 완료, future = " + future);
        es.close();
    }

    static class MyCallable implements Callable<Integer> {

        @Override
        public Integer call() throws Exception {
            log("Callable 시작");
            sleep(2000);
            int value = new Random().nextInt(10);
            log("create value = " + value);
            log("Callable 완료");
            return value;
        }
    }
}
```

- 실행 결과

### 동작 원리
- submit()을 호출해서 ExecutorService에 taskA를 전달함
- ExecutorService는 전달한 taskA의 미래 결과를 알 수 있는 Future 객체를 생성함
  - Future는 인터페이스 => 실제 구현체는 `FutureTask`
- 생성한 Future 객체 안에 taskA의 인스턴스를 보관함
- Future 내부에 taskA 작업의 완료 여부와, 작업 결과 값을 가짐
- submit()을 호출한 경우 Future가 만들어지고, 전달한 작업인 taskA가 바로 블로킹 큐에 담기는 것이 아니라, taskA를 감싸고 있는 Future가 대신 브로킹 큐에 담김
- 담고나면 바로 Future 객체(참조)를 바로 반환함
  - Not completed: 작업이 완료되지 않음
  - taskA의 인스턴스 주소를 가지고 있음
  - **생성한 Future는 즉시 반환됨**

- `참고로 Future의 구현체인 FutureTask는 Runnable 인터페이스도 함게 구현하고 있음`
  - 스레드 1은 FutureTask의 run() 메서드를 수행함
  - 그리고 run() 메서드가 taskA의 call() 메서드를 호출하고 그 결과를 받아서 처리함
  - FutureTask.run() -> MyCallable.call()

### 문제의 시작
- 스레드 1
  - 스레드 1은 taskA의 작업을 아직 완료하지 않음
- 요청 스레드
  - 요청 스레드는 Future 인스턴스의 참조를 가지고 있음
  - 그리고 언제든지 본인이 필요할 때 Future.get()을 호출해서 taskA의 작업의 미래 결과를 받을 수 있음
  - 요청 스레드는 작업의 결과가 필요해서 future.get()을 호출
    - Future에는 완료 상태가 있음 => taskA의 작업이 완료되면 Future의 상태도 완료로 변경됨
    - 여기서 taskA의 작업이 아직 완료되지 않음. 따라서 Future도 완료 상태가 아님
  - **요청 스레드가 future.get()을 호출하면 Future가 완료 상태가 될 때까지 대기함**
  - 이때 요청 스레드는 **RUNNABLE -> WAITING**이 됨

### future.get()을 호출했을 때
- Future가 완료 상태: Future가 완료 상태면 Future에 결과도 포함되어있음
  - 이 경우 요청 스레드는 대기하지 않고, 값을 즉시 반환받을 수 있음
- Future가 완료 상태가 아님: taskA가 아직 수행되지 않았거나 또는 수행 중이라는 것
  - 어쩔 수 없이 결과를 받기 위해서 대기해야함
  - 요청 스레드가 마치 락을 얻을 때처럼 결과를 얻기 위해 대기함
  - 이처럼 스레드가 어떤 결과를 얻기 위해 대기하는 것을 블로킹이라고 함

### 참고: 블로킹 메서드
- Thread.join(), Future.get()과 같은 메서드는 스레드가 작업을 바로 수행하지 않고, 다른 작업이 완료될 때까지 기다리게 하는 메서드
- 이러한 메서드를 호출하면 호출한 스레드는 지정된 작업이 완료될 때까지 블록(대기)되어 다른 작업을 수행할 수 없음

### 다시 돌아와서
- 요청 스레드
  - 대기 상태로 future.get()을 호출하고 대기 중
- 스레드 1
  - taskA 작업을 완료함
  - Future에 taskA의 반환 값을 담음
  - Future 상태를 완료로 변경
  - 요청 스레드를 깨움 => Waiting -> Runnable로 변함

### 정리
- Future는 작업의 미래 결과를 받을 수 있는 객체
- 따라서 submit() 호출 시, 즉시 반환됨
- 작업의 결과가 필요하면 future.get()을 호출하면 됨
  - 완료 상태: 즉시 반환
  - 미완료 상태: 블로킹

### Future가 필요한 이유?
- 의문: 그냥 es.submit()에서 바로 반환하게 하면 안되나? (값이 완료되었으면 바로 반환, 아니면 블로킹 하는건 같지 않을까?)
- 즉, 어차피 future.get()에서 블로킹이 될텐데 왜 분리했을까? (es.submit(), future.get())
- 왜 이런 개념이 필요할까? => 다음 챕터에서 배움

### 문제 상황
- 숫자를 나누어 더하는 기능을 멀티 스레드로 수행

```java
public class SumTaskMainV2 {

    public static void main(String[] args) throws ExecutionException, InterruptedException {
        ExecutorService es = Executors.newFixedThreadPool(2);
        Future<Integer> future1 = es.submit(new SumTask(1, 50));

                sum += i;
            }
            log("작업 완료 result = " + sum);
            return sum;
        }
    }
}
```

## Future 4 - 이유

### 필요한 이유
- es.submit(): 블로킹 X
- future.get(): 블로킹 O
- 만약 es.submit()에서 블로킹이 되고 바로 반환까지 한다면? (실제로는 없는 코드)
  - es.submit(task1): 2초 기다림
  - es.submit(task2): 2초 기다림
  - 총 4초가 걸림 (멀티 스레드를 사용하는 이유가 없어짐 - 사실상 단일 스레드)

### Future를 반환한다면?
- es.submit(task1): 즉시 수행
- es.submit(task2): 즉시 수행
- 즉, 병렬적으로 작업을 수행할 수 있음
- future.get()으로 작업을 가져올 때만, 값을 가져오긴 해야하니깐, 기다리는 것
  - future1.get()
  - future2.get()
  - 병렬적으로 실행되기 때문에, future1.get()에서 2초가 걸려도 future2.get()은 2초가 이미 지나서 작업이 완료되어서 총 2초만 기다리면 됨

### Future를 잘못 사용하는 예
- Future를 호출하자마자 바로 get()을 호출해도 문제가 될 수 있음
```java
es.submit(task1);
funture1.get();

es.submit(task2);
future2.get();
```
  - future1에서 2초의 블로킹이 걸리면서 사실상 단일 스레드 환경과 동일하게 됨
  - future1이 작업을 완료하는 동안 task2는 실행조차 못하고 있는 상황 (결국 다시 2초를 기다려야함)

```java
es.submit(task1).get();
es.submit(task2).get();
```
  - 이것도 사실상 4초가 걸리는 작업이 되어버림

### 정리
- Future라는 개념 덕분에 결과를 받을 때까지 요청 스레드는 대기하지 않고, 작업을 수행할 수 있음
- 요청 스레드가 필요할 때 Future.get()을 호출해서 최종 결과를 받을 수 있음
- 이러한 이유로 ExecutorService는 결과를 직접 반환하지않고 Future를 반환함

## Future 5 - 정리

### Future
- 작업의 미래를 나타내고, 계산이 완료되었는지 확인하고, 완료될 때까지 기다릴 수 있는 기능을 제공함
```java
public interface Future<V> {
    
    boolean cancel(boolean mayInterruptIfRunning);
    boolean isCancelled();
    
    boolean isDone();
    
    V get() throws InterruptedException, ExecutionException;
    v get(long timeout, TimeUnit unit)
      throws InterruptedException, ExecutionException, TimeoutException;
    
    enum State {
        RUNNING,
        SUCCESS,
        FAILED,
        CANCELLED
    }
    
    default State state() {}
}
```

### 주요 메서드
- boolean cancel(boolean mayInterruptIfRunning);
  - 기능: 아직 완료되지 않은 작업을 취소함
  - 매개변수: mayInterruptIfRunning
    - cancel(true): Future를 취소 상태로 변경
      - 이때 작업이 실행 중이라면 Thread.interrupt()를 호출해서 작업을 중단함
    - cancel(false): Future를 취소 상태로 변경함
      - 단 이미 실행 중인 작업은 중단하지 않음
    - 반환값: 작업이 성공적으로 취소된 경우 true, 이미 완료되었거나 취소할 수 없는 경우 false
    - 설명 작업이 실행 중이 아니거나 아직 시작되지 않았으면 취소하고, 실행 중인 작업의 경우 mayInterruptIfRunning이 true이면 중단을 시도함
    - 참고: 취소 상태의 Future.get()을 호출하면 CancellationException 런타임 에러가 발생함

- boolean isCancelled()
  - 기능: 작업이 취소되었는지 여부를 확인함
  - 반환값: 작업이 취소된 경우 true, 그렇지 않은 경우 false
  - 설명: 이 메서드는 작업이 cancel() 메서드에 의해 취소된 경우에 true를 반환함

- boolean isDone()
  - 기능: 작업이 완료되었는지 여부를 확인함
  - 반환값: 작업이 완료된 경우 true, 그렇지 않은 경우 false
  - 설명: **작업이 정상적으로 완료되었거나, 취소되었거나, 예외가 발생하여 종료된 경우에 true를 반환함**

- State state()
  - Future의 상탤를 반환함 - Java 19부터 지원함
  - RUNNING: 작업 실행 중
  - SUCCESS: 성공 완료
  - FAILED: 실패 완료
  - CANCELLED: 취소 완료

- V get()
  - 기능: 작업이 완료될 때까지 대기하고, 완료되면 결과를 반환함
  - 반환값: 작업의 결과
  - 예외
    - InterruptedException: 대기 중인 현재 스레드가 인터럽트 된 경우 발생
    - ExecutionException: 작업 계산 중에 예외가 발생한 경우 발생
  - 설명: 작업이 완료될 때까지 get()을 호출한 현재 스레드를 대기함. 작업이 완료되면 결과를 반환함

- V get(long timeout, TimeUnit unit)
  - 기능: get()과 동일하지만, 시간 초과되면 예외를 발생
  - 매개변수
    - timeout: 대기할 최대 시간
    - unit: timeout 매개변수 시간 단위 지정
  - 반환값: 작업의 결과
    - 예외
    - InterruptedException: 대기 중인 현재 스레드가 인터럽트 된 경우 발생
    - ExecutionException: 작업 계산 중에 예외가 발생한 경우 발생
    - TimeoutException: 주어진 시간 내에 작업이 완료되지 않은 경우 발생
  - 설명: 지정된 시간 동안 결과를 기다림. 시간이 초과되면 TimeoutException을 발생시킴

## Future 7 - 예외

### Future.get() 예외 받기
- Future.get()을 호출하면 작업의 결과뿐만 아니라 작업 중에 발생한 예외도 받을 수 있음
```java
public class FutureExceptionMain {

    public static void main(String[] args) {
        ExecutorService es = Executors.newFixedThreadPool(1);

        log("작업 전달");
        Future<Integer> future = es.submit(new ExCallable());
        sleep(1000); // 작업이 끝날 때까지 대기


        try {
            log("future.get() 호출 시도, future.state(): " + future.state());
            Integer result = future.get();
        } catch (InterruptedException e) {
            throw new RuntimeException(e);
        } catch (ExecutionException e) { // 실행 중 터지는 예외
            log("e = " + e);
            Throwable cause = e.getCause();
            log("cause = " + cause);
        }
    }

    static class ExCallable implements Callable<Integer> {

        @Override
        public Integer call() throws Exception {
            log("Callable 실행, 예외 발생");
            throw new IllegalStateException("ex!");
        }
    }
}
```
- 실행 결과

## ExecutorService - 작업 컬렉션 처리

### 작업 컬렉션 처리
- ExecutorService는 여러 작업을 한 번에 편리하게 처리하는 invokeAll(), invokeAny() 기능을 제공함
- invokeAll()
  - `<T> List<Future<T>> invokeAll(Collection<? extends Callable<T>> tasks) throws InterruptedException`
    - 모든 Callable 작업을 제출하고, 모든 작업이 완료될 때까지 기다림
  - `<T> List<Future<T>> invokeAll(Collection<? extends Callable<T>> tasks, long timeout, TimeUnit unit) throws InterruptedException`
    - 지정된 시간 내에 모든 Callable 작업을 제출하고 완료될 때까지 기다림

- invokeAny()
  - `<T> T invokeAny(Collection<? extends Callable<T>> tasks) throws InterruptedException, ExecutionException`
    - 하나의 Callable 작업이 완료될 때까지 기다리고, 가장 먼저 완료된 작업의 결과를 반환함
    - 완료되지 않은 나머지 작업은 취소됨
  - `<T> T invokeAny(Collection<? extends Callable<T>> tasks, long timeout, TimeUnit unit) throws InterruptedException, ExecutionException, TimeoutException`
    - 지정된 시간 내에 하나의 Callable 작업이 완료될 때까지 기다리고, 가장 먼저 작업의 결과를 반환함
    - 완료되지 않은 나머지 작업은 취소시킴

### 예제 코드
```java
public class InvokeAllMain {

    public static void main(String[] args) throws InterruptedException, ExecutionException {
        ExecutorService es = Executors.newFixedThreadPool(10);

        CallableTask task1 = new CallableTask("task1", 1000);
        CallableTask task2 = new CallableTask("task2", 2000);
        CallableTask task3 = new CallableTask("task3", 3000);

        List<CallableTask> tasks = List.of(task1, task2, task3);
        
        List<Future<Integer>> futures = es.invokeAll(tasks); // 세 작업이 모두 완료되어야 리턴을 함 = 여기서 블로킹 됨
        for (Future<Integer> future : futures) {
            Integer value = future.get();
            log("value = " + value);
        }

        es.close();
    }
}
```
- 실행 결과

```java
public class InvokeAnyMain {

    public static void main(String[] args) throws InterruptedException, ExecutionException {
        ExecutorService es = Executors.newFixedThreadPool(10);

        CallableTask task1 = new CallableTask("task1", 1000);
        CallableTask task2 = new CallableTask("task2", 2000);
        CallableTask task3 = new CallableTask("task3", 3000);

        List<CallableTask> tasks = List.of(task1, task2, task3);

        Integer value = es.invokeAny(tasks);
        log("value = " + value);

        es.close();
    }
}
```

## 추가 정리

### ExecutorService 주요 메서드 정리
- `void execute(Runnable command)`
- `<T> Future<T> submit(Callable<T> task)`
- `Future<?> submit(Runnable task)`
  - Runnable은 반환값이 없기 때문에 future.get()을 호출할 경우 null을 반환함

### ExecutorService 종료
- 자바 19부터 close()가 제공됨
- shutdown()을 포함한 ExecutorService 종료는 뒤에서 자세히 다룸
