# 동기화 - synchronized

## 출금 예제 - 시작

### 공유 자원
- 여러 스레드가 동시에 접근할 때 발생하는 동시성 문제
- 여러 스레드가 접근하는 자원을 **공유 자원**이라고 함
- 멀티 스레드를 사용하 때는 공유 자원에 대한 접근을 적절하게 동기화해서 동시서 문제가 발생하지 않게 방지하는 것이 중요함

### 예제 코드
```java
public class BankAccountV1 implements BankAccount {

    private int balance;

    public BankAccountV1(int balance) {
        this.balance = balance;
    }

    @Override
    public boolean withdraw(int amount) {
        log("거래 시작: " + getClass().getSimpleName());

        log("[검증 시작] 출금액: " + amount + ", 잔액: " + balance);
        if (balance < amount) {
            log("[검증 실패] 출금액: " + amount + ", 잔액: " + balance);
            return false;
        }

        log("[검증 완료] 출금액: " + amount + ", 잔액: " + balance);
        sleep(1000); // 출금에 걸리는 시간
        balance -= amount;
        log("[출금 완료] 출금액: " + amount + ", 잔액: " + balance);

        log("거래 종료: " + getClass().getSimpleName());
        return true;
    }

    @Override
    public int getBalance() {
        return balance;
    }
}
```

```java
public class BankMain {

    public static void main(String[] args) throws InterruptedException {
        BankAccount bankAccount = new BankAccountV1(1000);

        Thread t1 = new Thread(new WithdrawTask(bankAccount, 800), "t1");
        t1.start();
        t1.join();

        log("최종 잔액: " + bankAccount.getBalance());
    }
}
```

## 동시성 문제

### 은행 예제에서 발생하는 이유 - t1이 조금 더 빨리 실행될 때
- t1이 검증 로직을 통과하고 돈을 인출하기 위해서 어떤 과정을 진행하고 있고, 실질적으로 잔액을 아직 줄이지 않았을 때
- t2가 검증 로직을 통과하게 되면서 문제가 발생함
- 로직은 둘 다 실행이 되었기 때문에 1600원을 출금하게 됨

### 은행 예제에서 발생하는 이유 - 완전히 동시에 실행될 때
- 검증 로직은 둘 다 통과함
- balance -= amount 이 부분도 동시에 실행됨
  - 같은 balance가 둘 다 10000원으로 일고 amount를 빼면 200원 잔액이 남게됨
- 로직은 둘 다 실행이 되었기 때문에 1600원을 출금하게 됨

- balance =- amount => 코드 한 줄인데?라고 할 수 있지만
  - 실제로는 balance를 가져오고
  - balance에서 amount를 빼고
  - balance를 다시 갱신하고
  - 이렇게 또 세부적으로 쪼개져있고
  - balance를 가져오는 그 단계가 동시에 실행된다면 같은 1000원을 바라보고 있게 됨

## 임계 영역

### 문제가 발생하는 근본적인 원인
- 여러 스레드가 함께 사용하는 공유 자원을 여러 단계로 나누어 사용하기 때문
  - 검증 단계
  - 출금 단계

### 공유 자원
- balance
- 다른 스레드에서 계산하는 도중에 해당 값을 얼마든지 변경할 수 있음

### 한 번에 하나의 스레드만 실행
- t1, t2 스레드가 함께 출금()을 호출하면 t1 스레드가 먼저 처음부터 출금()을 완료하도록 구성한다면 문제가 발생하지 않음
  - 단, 여러 스레드를 사용하는 이유가 없음

### 임계 영역 (Critical Section)
- 여러 스레드가 동시에 접근하면 데이터 불일치나 예상치 못한 동작이 발생할 수 있는 위험한 영역
- 여러 스레드가 동시에 접근해서는 안되는 공유 자원을 접근하거나 수정하는 부분을 의미함
  - 공유 변수나 공유 객체를 수정
  - **출금 로직**

- `임계 영역은 한 번에 하나의 스레드만 접근할 수 있도록 보호해야함`

## synchronized 메서드

### 예제 코드
```java
public class BankAccountV2 implements BankAccount {

    private int balance;

    public BankAccountV2(int balance) {
        this.balance = balance;
    }

    @Override
    public synchronized boolean withdraw(int amount) {
        log("거래 시작: " + getClass().getSimpleName());

        log("[검증 시작] 출금액: " + amount + ", 잔액: " + balance);
        if (balance < amount) {
            log("[검증 실패] 출금액: " + amount + ", 잔액: " + balance);
            return false;
        }

        log("[검증 완료] 출금액: " + amount + ", 잔액: " + balance);
        sleep(1000); // 출금에 걸리는 시간
        balance -= amount;
        log("[출금 완료] 출금액: " + amount + ", 잔액: " + balance);

        log("거래 종료: " + getClass().getSimpleName());
        return true;
    }

    @Override
    public int getBalance() {
        return balance;
    }
}
```
- 실행 결과
    ```text

    19:00:15.125 [       t1] [검증 시작] 출금액: 800, 잔액: 1000
    19:00:15.126 [       t1] [검증 완료] 출금액: 800, 잔액: 1000

    19:00:16.128 [       t2] 거래 시작: BankAccountV2
    19:00:16.128 [       t2] [검증 시작] 출금액: 800, 잔액: 200
    19:00:16.129 [       t2] [검증 실패] 출금액: 800, 잔액: 200
    ```

    - 메서드에 synchronized 키워드를 사용하면 해당 메서드는 한 번에 하나의 스레드에서만 실행할 수 있게 됨

### synchronized 분석
- 모든 객체는 내부에 자신만의 락을 가지고 있음 (모니터 락)
- 스레드가 synchronized 키워드가 있는 메서드에 진입하려면 해당 인스턴스의 락이 반드시 필요함
- 실행 과정
  - t1이 먼저 실행된다고 가정
  - 스레드 t1이 락을 획득함 => 출금 메서드에 진입 가능
  - t2도 실행을 하려고 함 => 락 획득 실패
    - **Blocked 상태로 대기함**
    - **락을 획득할 때까지 무한정 대기함**
    - CPU 스케쥴링에 들어가지 않음
  - t1이 출금()을 완료 및 락을 반납
  - t2가 기다리던 락이 왔기 때문에 락을 획득함
  - 검증에서 실패하여 인출되지 않음 (정상동작)
  - 총 잔액이 200원 출금액 800원 한 번 정상적으로 동작하게 됨 (기대한 동작)

### 참고
- 락을 획득하는 순서는 보장되지 않음
- 락을 획득하는지는 자바 표준에 정의되어있지 않음
  - 확률적으로 오래 기다린 애가 받을 수 있음 / 최근에 들어온 애가 얻을 수도 있음

- volatile을 사용하지 않아도 synchronized 안에서 접근하는 변수의 메모리 가시성 문제는 해결됨

## synchronized 코드 블럭

### 단점
- 한 번에 하나의 스레드만 실행할 수 있다는 점
- 여러 스레드가 동시에 실행하지 못하기 때문에, 전체로 보면 성능이 떨어질 수 있음
- 따라서 synchronized를 통해 동시에 실행할 수 없는 코드 구간은 꼭!!! 필요한 곳에서만 설정해야함

- 해결을 하는 방향성: 한 번에 하나의 스레드가 실행할 수 있는 영역을 정말 작게 유지하는 것

### 진짜 임계 영역
```java
log("[검증 시작] 출금액: " + amount + ", 잔액: " + balance);
if (balance < amount) {
    log("[검증 실패] 출금액: " + amount + ", 잔액: " + balance);
    return false;
}

log("[검증 완료] 출금액: " + amount + ", 잔액: " + balance);
sleep(1000); // 출금에 걸리는 시간
balance -= amount;
log("[출금 완료] 출금액: " + amount + ", 잔액: " + balance);
```
- 자바에서는 특정 코드 영역에대해서 synchronized를 걸 수 있는 기능이 있음

### 코드 블럭
```java
public class BankAccountV3 implements BankAccount {

    private int balance;

    public BankAccountV3(int balance) {
        this.balance = balance;
    }

    @Override
    public boolean withdraw(int amount) {
        log("거래 시작: " + getClass().getSimpleName());

        synchronized (this) {
            log("[검증 시작] 출금액: " + amount + ", 잔액: " + balance);
            if (balance < amount) {
                log("[검증 실패] 출금액: " + amount + ", 잔액: " + balance);
                return false;
            }

            log("[검증 완료] 출금액: " + amount + ", 잔액: " + balance);
            sleep(1000); // 출금에 걸리는 시간
            balance -= amount;
            log("[출금 완료] 출금액: " + amount + ", 잔액: " + balance);
        }

        log("거래 종료: " + getClass().getSimpleName());
        return true;
    }

    @Override
    public synchronized int getBalance() {
        return balance;
    }
}
```
- synchronized (this) {}: 안전한 임계 영역 코드 블럭으로 지정
- 이렇게 하면 꼭 필요한 코드만 안전하게 임계 영역으로 들어갈 수 있음
- this: 락을 획득할 인스턴스의 참조
  - BankAccountV3의 인스턴스 락을 사용하므로 해당 인스턴스의 참조인 this를 넣어주면 됨

### 해결할 수 있는 문제
- 경합 조건(Race Condition): 두 개 이상의 스레드가 경쟁적으로 동일한 자원을 수정할 때 발생하는 문제
- 데이터 일관성: 여러 스레드가 동시에 읽고 쓰는 데이터의 일관성 유지
- 주의: 동기화는 멀티스레드 환경에서 필수적인 기능이지만 남발하면 성능 저하를 초래할 수 있으므로 꼭 필요한 곳에 적절히 사용해야함
